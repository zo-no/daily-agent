# 个人反馈回路与 Agent 渐进自动化

## 核心产品心智

Log Note 的用户心智不是“把今天写下来”，而是：

> 通过记录观察自己当前的生活系统，对它进行阶段性评价，再尝试一次小幅优化，通过新的记录验证改变是否有效。

产品的核心循环是：

> 记录 → 理解 → 评价 → 调整 → 验证 → 更新理解

用户不是一次制定一套完美计划，而是把自己的生活当成一个可持续观察和优化的系统。

## 一、什么是“当前系统”

用户的现状不应只被总结成“自律”或“不自律”，而应当被理解为多个可观察因素之间的互动：

- 输入：饮食、睡眠、信息、人际交流、工作任务。
- 环境：时间、地点、设备、他人、外部要求。
- 内部状态：精力、情绪、压力、健康状况。
- 行为：实际做了什么，在什么时候做。
- 结果：是否完成、感受如何、是否需要恢复。
- 约束：工作、家庭、健康、资源和现实时间。

Agent 需要理解的不只是“用户有什么习惯”，还包括这些习惯在什么条件下出现、为什么能持续，以及产生了什么结果。

## 二、个人反馈回路

### 1. 记录：获得真实样本

记录的目标不是让用户填满所有字段，而是持续获得足够真实的生活样本。

因此，记录必须：

- 低成本。
- 允许碎片化。
- 允许不完整。
- 不强迫用户在当下分类和分析。
- 保留当时的原始表达。

### 2. 理解：把碎片转化为模式

AI 通过用户已有标签、事件时间、重复主题和结果反馈，帮助用户看到：

- 哪些事情经常一起出现。
- 哪些状态正在反复发生。
- 哪些目标只停留在意图中。
- 哪些做法曾经真正带来好结果。

AI 笔记分组属于这一层，它把未组织的记录转化为可观察的主题，但本身不是最终价值。

### 3. 评价：判断是否正在接近目标

评价必须相对于用户自己的目标、期望和约束，而不是使用平台统一标准。

好的评价需要区分：

- 事实：过去七天有四天在凌晨一点后入睡。
- 结果：其中三天的次日精力评价较低。
- 关联：较晚入睡与次日低精力同时出现。
- 假设：提前入睡可能改善第二天状态。

### 4. 调整：每次只改变一个关键变量

Agent 不应该直接给出一份庞大的人生改造计划，而应当提出小幅、可执行、可撤销和可验证的调整。

例如：

> 接下来三天，尝试在晚上 12 点前停止高刺激的信息输入，继续记录入睡时间和第二天上午精力。

### 5. 验证：检查调整是否对这个用户有效

实验结束后，Agent 不应只询问“是否完成”，还要比较：

- 实际是否执行。
- 目标结果是否改善。
- 是否引入新成本或副作用。
- 用户是否愿意继续。
- 建议应被保留、修改还是放弃。

## 三、Agent 的角色

Agent 不应该是人生评委、纪律监督者或替用户决定的管理者。

它更像：

- 观察者：帮助发现容易被忽略的模式。
- 分析者：区分事实、相关和假设。
- 实验助手：设计低成本的微型调整。
- 记录员：追踪用户尝试过什么以及结果如何。
- 合作者：在用户授权后帮助执行具体动作。

一句话定义：

> Agent 通过持续观察帮用户看清自己，通过小步实验帮用户改变自己。

## 四、Agent 自动化的渐进层级

Agent 的自动化能力不应该一步到位，而应当由用户信任和明确授权逐步开放。

### L0：整理

- 智能分组。
- 匹配用户已有标签。
- 生成日、周、月摘要。

### L1：观察

- 描述趋势。
- 发现重复模式。
- 提示可能的相关性。
- 指出目标与行动的偏离。

### L2：建议

- 提出一个可验证的微型调整。
- 说明建议来自哪些观察。
- 说明预期改善的结果和可能成本。

### L3：协助执行

在用户确认后：

- 创建提醒。
- 安排日程。
- 生成待办。
- 在合适时间发起状态询问。
- 实验结束后请求用户反馈。

### L4：有限自动化

用户可以对特定领域授予持续权限，例如：

- 每当连续晚睡三天，自动建议一个提前放下手机的日程。
- 学习计划连续延迟时，自动把下一步拆成更小任务。
- 在已批准的时间范围内调整提醒。

任何自动化都应当：

- 按领域单独授权。
- 设置明确边界。
- 展示本次执行原因。
- 允许撤销、暂停和关闭。
- 不从某一领域的授权推导出其他权限。

## 五、一个完整示例

### 记录

用户在两周内多次记录：

- 午餐后很困。
- 下午学习计划延迟。
- 饭后需要喝咖啡。
- 饮食较轻的日子状态较好。

### Agent 观察

> 过去两周共记录了 5 次明显的下午困倦，其中 4 次发生在用户自述午餐较重的日子。这是相关性，暂时不足以证明因果。

### Agent 建议

> 接下来三个工作日，选择一份较轻的午餐，并在下午三点记录一次精力。其他作息尽量保持不变。

### 用户授权协助

Agent 询问：

> 是否在这三天的下午三点提醒你记录精力？

### 验证结果

三天后，Agent 对比记录，询问用户主观感受，再决定：

- 延长实验。
- 将其保留为习惯。
- 更换变量继续验证。
- 判定此假设对用户暂时无效。

## 六、产品数据不应只有“记录”

为了支持完整回路，产品长期需要区分三类数据：

### 原始记录

用户在当时写下的事实、感受和想法，永远保留原文。

### 派生观察

AI 根据多条记录生成的摘要、分组、趋势、关联和假设。它们都需要标明来源，并可以被更新或删除。

### 干预与结果

记录 Agent 提出了什么建议、用户是否采纳、实际是否执行，以及最终结果如何。

这一层数据会帮助 Agent 逐渐从“给出通用建议”变成“知道什么对这个用户真正有效”。

## 七、产品的核心指标

如果这是产品的核心心智，主指标就不应只是记录数、打开次数或用户时长。

更有意义的指标包括：

- 用户完成了多少次“记录—调整—验证”回路。
- Agent 的观察被用户认为准确的比例。
- 建议被采纳和真正执行的比例。
- 用户完成微型实验的比例。
- 被验证有效的调整有多少被保留为长期习惯。
- 用户是否觉得自己对生活的理解和控制感在提高。

## 八、关键产品原则

- 记录真实重于记录完整。
- 观察与评判分开。
- 相关性与因果关系分开。
- 一次优先改变一个关键变量。
- Agent 说明建议依据，但不伪造确定性。
- 建议默认需要用户确认。
- 自动化需要逐领域、逐能力授权。
- 所有自动动作都可暂停、撤销和回顾。
- 优化目标由用户定义，不由平台统一定义。
- 产品最终应当提高用户的自主性，而不是对 Agent 的依赖。

## 九、当前阶段的产品重点

当前不需要立即实现完整自动化。可以优先建立最小闭环：

1. 用户持续记录。
2. 用户主动点击智能整理或生成阶段回顾。
3. Agent 只描述一个有足够记录支持的模式。
4. Agent 提出一个微型调整建议。
5. 用户决定是否将它转化为一个短期实验。
6. 产品在实验结束后对比结果。

这个小回路一旦真正对用户有用，提醒、日程、设备和其他 Agent 的自动化才有继续生长的基础。
