# Log Note｜多 Agent 个人操作系统 PRD v0.1

> 文档状态：初版讨论稿，不代表开发承诺
> 创建日期：2026-08-14
> 产品阶段：现有 MVP 收口；下一阶段产品定义
> 产品定位：以 Universal Log 为数据底座的个人 Agent OS
> 核心口号：记录一切可理解，理解一切可改进。

## 1. 执行摘要

Log Note 的长期方向不是再做一个笔记工具、时间统计工具或通用 AI 助手，而是建立一套可被个人长期拥有的运行系统：

1. 用柳比歇夫式时间日记和自然记录，持续捕捉真实发生的事件、行为、状态、目标与结果。
2. 将来自不同领域、不同工具和不同格式的信息统一为可追溯的 `Log`。
3. 由 AI 把自然语言和系统事件编译为可计算、可验证、可撤销的语义结构。
4. 由健康、学习、工作、生活、时间等领域 Agent 分别理解局部问题。
5. 由主 Agent 在用户目标、现实约束和领域冲突之间做协调，只提出或执行被授权的下一步。
6. 通过“记录 → 分析 → 干预 → 验证”积累个人因果证据，逐步拟合更适合用户自己的优秀 Log 曲线。

这里的 **All in one** 指所有个人活动最终进入同一套事件模型、权限模型和反馈闭环，不表示把所有功能、控件和 Agent 同时放到首页。

这里的 **优秀曲线** 不是平台定义的统一人生评分，而是：

> 在用户主动设定的目标与现实约束下，更稳定地产生期望结果、且代价可以接受的个人轨迹。

## 2. 文档要解决的问题

当前 Log Note 已证明可以作为一个安静、本地优先、移动优先的记录 MVP，但“记录之后发生什么”仍未产品化：

- 记录散落在日记、时间、健康、工作、学习和设备活动中，无法形成同一条个人时间线。
- 用户有大量事实，却很难从事实中持续发现模式、验证假设和更新行动。
- 通用 AI 助手缺少长期、可信、可追溯的个人上下文，建议容易泛化或失真。
- 单一 Agent 容易跨领域越权，也难以解释健康、工作、学习目标之间的冲突。
- 传统效率产品只管理待办，传统量化产品只展示统计，都没有完成“观察—行动—结果”的闭环。

本 PRD 用于定义 Log Note 从“个人记录工具”演进为“多 Agent 个人操作系统”的产品模型、首个验证闭环、功能边界与阶段路线。

## 3. 产品愿景与定位

### 3.1 一句话定位

Log Note 是一个以日志为数据底座的个人 Agent OS：它把时间、行为、状态、目标和数字活动统一记录为 Log，由多个领域 Agent 分析、协作和执行，再通过真实结果持续拟合更适合用户的优秀轨迹。

### 3.2 产品心智

用户不是在“记更多笔记”，而是在维护并改进自己的个人运行系统：

```text
记录真实世界
    ↓
理解当前系统
    ↓
发现一个关键变量
    ↓
授权一次微小干预
    ↓
观察真实结果
    ↓
更新对自己的理解
```

### 3.3 核心差异

| 产品类型 | 主要能力 | 关键缺口 | Log Note 的差异 |
| --- | --- | --- | --- |
| 笔记工具 | 保存内容 | 缺少时间化、行为化反馈闭环 | 原始记录进入可计算但不改原文的 Log 体系 |
| 时间统计工具 | 统计投入 | 很难连接状态、环境、结果与原因 | 时间只是 Universal Log 的一个维度 |
| 健康/习惯 App | 单领域追踪 | 数据孤岛，目标之间无法协调 | 多领域 Agent 共享同一事实底座，由主 Agent 协调 |
| 通用 AI 助手 | 问答、生成、执行 | 缺少可信长期数据和结果验证 | 每项观察引用原始 Log，每项建议进入实验并验证 |
| 待办/日历工具 | 管理计划 | 计划与真实行为断裂 | 同时记录计划、执行、状态、结果与偏差 |

## 4. 产品边界与能力状态

PRD 必须区分已经存在、下一阶段要验证和长期愿景，宣传与演示也必须使用同一口径。

### 4.1 已实现：当前可演示 MVP

- 本地优先、移动优先的 PWA。
- 普通记录新增、浏览、搜索、编辑和删除。
- 日期时间线与领域/分类视图。
- 领域、分类、模板与周期模板管理。
- 结构化字段、固定记录和自由文本 Markdown。
- 中英文界面。
- 完整 JSON 备份/安全恢复、可读 Markdown 导出。
- 本地图片附件与便携附件备份。
- 离线壳、离线记录与刷新后持久化。
- 当前无账号、无服务端数据库、无自动上传。

### 4.2 下一阶段：需要产品、架构与隐私评审后验证

- Universal Log 语义模型。
- 柳比歇夫式活动计时与时间账本。
- AI 匹配用户已有标签，生成可撤销的派生语义。
- 用户主动触发的阶段回顾。
- 一个有来源的观察、一个微型调整、一个 3–7 天实验。
- 实验结束后的前后对比与用户结果判断。
- 单个只读领域 Agent 原型和主 Agent 汇总原型。

### 4.3 远期愿景：尚未承诺实现

- 健康、学习、工作、生活、时间等多领域 Agent。
- Agent 间任务协作、冲突协调与受控执行。
- 日程、提醒、待办、设备或第三方系统的有限自动化。
- 个人历史最佳曲线、情景推演和偏航提醒。
- 匿名群体参考曲线、领先轨迹匹配与关系匹配。
- 多设备同步、账号、远端数据库和跨应用连接器。

## 5. 目标用户与核心场景

### 5.1 首要用户

现阶段首要用户仍是产品作者本人，以及愿意长期进行低负担个人记录、希望理解并改善自身状态的人。

典型特征：

- 同时管理工作、学习、健康和生活目标。
- 已经使用笔记、日历、待办或健康工具，但信息分散。
- 愿意记录事实，但不愿每天填写复杂表格。
- 不满足于周报总结，希望知道“什么对自己真正有效”。
- 对个人数据隐私、AI 误判和自动化越权敏感。

### 5.2 核心待办任务（JTBD）

> 当生活持续发生、我的注意力被多个目标分散时，我希望用最低成本留下真实 Log，并让系统基于可追溯证据帮助我看清当前轨迹、选择一个值得改变的变量、执行一次可控实验，从而逐渐知道什么方式更适合我。

### 5.3 首个端到端场景

1. 用户连续记录至少 14 天，包括自由文字、时间投入和少量周期状态。
2. AI 将记录匹配到用户已有标签，不改动原文。
3. 用户主动生成“当前轨迹”。
4. 时间 Agent 或领域 Agent 提出一个有来源的模式。
5. 主 Agent 将该模式与用户当前目标和约束对齐。
6. 系统只提出一个 3–7 天微型实验。
7. 用户明确接受，必要时单独授权提醒。
8. 实验结束后，系统对比执行、结果、成本和副作用。
9. 用户判断建议有效、无效或需要修改。
10. 结论成为可撤销的个人经验，不回写或篡改原始记录。

## 6. 核心概念模型

### 6.1 Universal Log

Universal Log 是产品的统一事实入口。它不是要求用户手动填写统一大表，而是一套能兼容不同来源的事件模型。

每条 Log 至少包含：

| 字段 | 含义 | 要求 |
| --- | --- | --- |
| `id` | 稳定标识 | 不因 AI 重算改变 |
| `occurredAt` | 实际发生时间 | 与创建时间分开 |
| `recordedAt` | 被记录时间 | 用于判断回忆偏差 |
| `source` | 来源 | 手动、模板、导入、设备或 Agent |
| `rawContent` | 原始内容 | 用户原文只由用户显式修改 |
| `domain/category/template` | 当前组织结构 | 兼容现有模型 |
| `duration` | 可选持续时间 | 支持柳比歇夫式时间账本 |
| `attachments` | 可选附件引用 | 本地权威、备份兼容 |
| `provenance` | 来源与变更链 | 所有导入和派生均可追溯 |

Universal Log 可以表达：

- 一段自然语言日记。
- 一次开始/结束明确的活动。
- 一个健康或周期指标。
- 一项目标、计划或承诺。
- 一个实际执行动作。
- 一个状态变化或环境事件。
- 一个结果、反馈或复盘判断。
- 经用户授权导入的系统事件。

### 6.2 柳比歇夫式时间日记

产品吸收柳比歇夫时间统计法的核心：记录时间实际花在了哪里，以长期事实校准自我认知，而不是要求用户预先排满计划。

首期原则：

- 允许快速开始、结束或事后补记活动。
- 活动时长是 Log 的可选维度，不是每条记录必填。
- 支持按日、周、领域、目标查看投入与偏差。
- 计划时间与实际时间分开保存。
- 时间数据可与精力、情绪、环境和结果关联，但不得宣称相关即因果。
- 首页快速记录步骤不得因此增加。

### 6.3 AI 语义编译层

AI 不拥有原始记录，只负责生成派生结构。其工作类似“语义编译”：

```text
自然记录 / 时间活动 / 系统事件
              ↓
用户已有标签 + 事件/状态/目标/结果语义
              ↓
可搜索、可聚合、可引用、可重算的派生 Log
```

AI 输出必须满足：

- 引用所依据的原始 Log。
- 区分事实、摘要、关联、假设和建议。
- 带模型版本、生成时间和置信信息。
- 可以接受、纠正、撤销、删除和重新计算。
- 低置信度时不分类、不推断。
- 不从单条普通记录推断人格、疾病或长期意图。
- 不自动创造用户标签；新标签默认需要用户确认。

### 6.4 多 Agent 体系

#### 主 Agent（Chief Agent）

主 Agent 是用户唯一的总体协作入口，负责：

- 理解用户当前目标、优先级和现实约束。
- 接收领域 Agent 的观察，而不是重复做全部专业分析。
- 发现跨领域冲突，例如工作投入改善但睡眠持续恶化。
- 对建议进行排序，每次最多把一个关键调整带到用户面前。
- 管理权限、执行预算、暂停状态和审计记录。
- 在证据不足或高风险时停止并请求用户判断。

主 Agent 不是用户的老板，也不能自行定义“优秀”。

#### 领域 Agent

| Agent | 关注对象 | 典型输入 | 典型输出 | 默认权限 |
| --- | --- | --- | --- | --- |
| 时间 Agent | 时间投入、节奏、计划偏差 | 活动时长、日历、目标 | 时间账本、投入偏差、节奏观察 | 只读 |
| 健康 Agent | 睡眠、饮食、运动、身体反馈 | 周期记录、健康 Log | 相关性观察、低风险实验建议 | 只读 |
| 学习 Agent | 输入、练习、输出、掌握度 | 学习 Log、作品、复盘 | 学习路径观察、下一步实验 | 只读 |
| 工作 Agent | 项目、深度工作、交付、阻塞 | 工作 Log、任务结果 | 项目轨迹、瓶颈与复盘 | 只读 |
| 生活 Agent | 情绪、关系、恢复与日常事件 | 日记、状态、事件 | 生活节奏与恢复观察 | 只读 |

领域 Agent 必须共享事实底座，但权限彼此隔离。健康领域的授权不能自动扩展为读取或操作工作系统。

#### 策略与审计层

所有 Agent 之上需要一层不可绕过的策略：

- 数据范围：本次可读取哪些 Log。
- 能力范围：只读、建议、创建草稿、执行。
- 领域范围：健康、工作等逐项授权。
- 时间范围：一次、到期日或持续授权。
- 成本范围：调用次数、费用和外部写操作限制。
- 审计记录：谁基于什么证据做了什么。
- 紧急停止：用户可一键暂停全部自动化。

### 6.5 反馈闭环数据

产品长期需要将数据分为六层，不能只保存“记录”和“AI 文案”：

1. **Raw Log**：用户或系统留下的原始事实。
2. **Derived Semantic**：标签、实体、事件类型和关系。
3. **Observation**：带来源的趋势、摘要和相关性。
4. **Goal & Constraint**：用户目标、优先级、资源和现实限制。
5. **Intervention**：建议、用户决定、实验方案和授权动作。
6. **Outcome**：执行情况、结果、成本、副作用和用户判断。

任何上层数据都可以删除和重算，但不能静默改写下层 Raw Log。

## 7. “优秀 Log 曲线”的产品定义

### 7.1 曲线不是单一分数

个人轨迹由多个随时间变化的维度共同组成，例如：

- 时间投入与切换成本。
- 睡眠、精力与恢复。
- 情绪、压力和稳定性。
- 学习输入、练习和输出。
- 工作产出、阻塞和交付。
- 关系、独处与生活事件。
- 目标、实际行动和结果偏差。

产品不得输出一个不可解释的“人生总分”。默认展示应是多维趋势、证据和取舍。

### 7.2 参考曲线优先级

1. 用户自己的历史最佳时期。
2. 用户明确选择的个人目标轨迹。
3. 有专业证据支持、且符合用户约束的方法。
4. 与用户背景和约束相似的匿名群体轨迹。

在个人闭环未验证前，不进入跨用户拟合。

### 7.3 拟合过程

```text
当前轨迹
  + 用户目标
  + 现实约束
  + 历史有效经验
  + 可接受成本
        ↓
选择一个可能关键的变量
        ↓
进行 3–7 天微型实验
        ↓
比较结果、成本与副作用
        ↓
更新个人有效路径
```

### 7.4 曲线输出的证据等级

| 等级 | 产品用语 | 含义 |
| --- | --- | --- |
| E0 | 记录事实 | 直接来自原始 Log |
| E1 | 描述趋势 | 多条记录的统计或摘要 |
| E2 | 发现关联 | 两类变量同时变化，不代表因果 |
| E3 | 待验证假设 | 有理由尝试微型实验 |
| E4 | 个人有效证据 | 对该用户有重复实验或稳定结果支持 |
| E5 | 外部专业证据 | 有可信来源，但仍需结合个人约束 |

所有建议必须展示其证据等级，禁止把 E2 相关性包装成 E4 因果结论。

## 8. 信息架构与核心产品面

### 8.1 首页：快速记录

首页继续只有一个首要任务：快速留下 Log。

- 一步打开普通记录，一步保存。
- 模板、领域、时长和标签均为可选。
- AI 不弹窗打断保存。
- Agent 入口不抢占首页首要 CTA。
- 保存后原文立即成为本地权威数据。

### 8.2 时间账本

用于回答“时间实际上去了哪里”：

- 快速开始/停止活动。
- 事后补记时间段。
- 计划与实际对比。
- 日/周/月投入分布。
- 中断、切换和未归类时间。
- 与状态、结果和目标的可选关联。

### 8.3 Universal Timeline

把自然记录、周期记录、时间活动、实验和结果放在同一时间轴中，同时允许按领域、标签、目标和来源切片查看。

时间线中的原始 Log 与 AI 派生信息必须有明确视觉区别。

### 8.4 Agent Center

Agent Center 是次级工作区，不进入普通快速记录路径，包含：

- 主 Agent 的本周摘要。
- 各领域 Agent 的状态、最后分析时间和待确认事项。
- Agent 可读取的数据范围。
- 建议、草稿动作和已执行动作。
- 权限、暂停、撤销和审计入口。

### 8.5 当前轨迹

用于回答三个问题：

1. 最近发生了什么？
2. 哪个变量可能最值得关注？
3. 下一步最小可验证调整是什么？

默认只给一个主观察和一个候选实验，不生成冗长的人生报告。

### 8.6 实验工作区

每个实验包含：

- 想验证的假设。
- 引用的证据 Log。
- 只改变的关键变量。
- 计划持续时间，默认 3–7 天。
- 目标结果和需要观察的成本/副作用。
- 用户是否接受及授权了哪些协助。
- 实际执行记录。
- 结束后的前后对比和用户结论。

## 9. 详细功能需求与优先级

### P0：现有记录底座与兼容性

| 功能 | 用户价值 | 关键要求 | 验收重点 |
| --- | --- | --- | --- |
| 快速记录 | 不中断生活地留下真实样本 | 不新增必填项或默认弹窗 | 打开和保存步骤不增加 |
| 原始 Log 不变性 | 保证长期信任 | AI、迁移、导入不得静默改写原文 | 可对比、可恢复 |
| 安全备份恢复 | 保证个人数据所有权 | 新数据层进入版本化备份；坏输入不覆盖当前数据 | 旧备份兼容、恢复事务安全 |
| 离线降级 | 无网仍可记录和查阅 | Agent 不可用时核心循环完整可用 | 离线 E2E 通过 |

### P1：AI 语义与最小反馈闭环

| 功能 | 用户价值 | 关键要求 | 成功/退出条件 |
| --- | --- | --- | --- |
| 已有标签匹配 | 降低整理成本 | 最多 3 个；低置信不打；可一键纠正 | 让记录更易找回，否则保持隔离 |
| 阶段回顾 | 看见近期事实和模式 | 用户主动触发；引用来源；区分事实与推断 | 用户认可准确且有用 |
| 当前轨迹 | 将多条 Log 变成可理解趋势 | 只输出一个关键观察 | 14 天数据后仍无价值则不扩展 |
| 微型实验 | 把建议变成可验证行动 | 一次一个变量；3–7 天；显式接受 | 完成前后对比和结果判断 |
| 结果记忆 | 让系统知道什么对个人有效 | 保存执行、结果、成本、副作用 | 可撤销、删除、备份和重算 |

### P2：多 Agent 协作

| 功能 | 用户价值 | 关键要求 | 启动条件 |
| --- | --- | --- | --- |
| 领域 Agent | 提供专业化视角 | 默认只读；数据范围隔离 | P1 闭环被验证有效 |
| 主 Agent 协调 | 解决跨领域目标冲突 | 解释排序理由；一次一个建议 | 至少两个领域产生可信观察 |
| 权限中心 | 可控开放执行能力 | 逐领域、逐动作、逐时间授权 | 任何外部写操作前必须具备 |
| Agent 审计 | 追溯每次分析和动作 | 展示依据、权限、结果 | 与执行能力同步上线 |

### P3：有限执行与生态连接

| 功能 | 用户价值 | 关键要求 | 启动条件 |
| --- | --- | --- | --- |
| 提醒/日程草稿 | 降低执行成本 | 默认只生成草稿，用户确认后写入 | 实验提醒被证明有用 |
| 有限自动执行 | 在固定边界内减少重复操作 | 可暂停、可撤销、有预算、有原因 | 单领域逐项授权和安全评审 |
| 第三方连接器 | 汇聚数字活动 Log | 默认不上传；明确同步方向和删除语义 | 架构、隐私、凭据方案批准 |

### P4：参考曲线与跨用户网络

匿名群体曲线、领先轨迹匹配、搭子关系和 Dating 不属于当前阶段。只有个人历史曲线、派生数据可信度和微型实验价值都被验证后，才允许另行立项。

## 10. Agent 权限与自动化分级

| 等级 | 能力 | 默认状态 | 用户控制 |
| --- | --- | --- | --- |
| L0 整理 | 标签、分组、摘要 | 主动触发 | 可纠正、撤销、重算 |
| L1 观察 | 趋势、相关、偏航 | 主动触发或订阅 | 可关闭领域观察 |
| L2 建议 | 微型实验建议 | 需要确认 | 接受、拒绝、修改 |
| L3 协助 | 提醒、日程、待办草稿 | 默认关闭 | 每次确认或有限授权 |
| L4 有限自动化 | 在明确规则内执行 | 默认关闭 | 逐领域授权、预算、到期、暂停、撤销 |

任何权限升级必须由用户明确操作。系统不能因为用户接受过一次建议，就推导出持续执行权限。

## 11. 关键交互规则

- AI 结果与原始记录在视觉和数据上分层。
- 每条观察可以展开查看引用 Log。
- 每条建议必须说明“为什么是现在、依据是什么、预计成本是什么”。
- 用户可以标记“准确 / 不准确 / 有用 / 无用”。
- 用户否定观察时，系统保留否定记录，但不修改原始 Log。
- 所有 Agent 动作提供撤销或可恢复替代方案。
- 高风险健康、心理、金融和人身安全场景只提供事实整理与寻求专业帮助提示，不进行诊断或自主执行。
- Agent 不以羞辱、人格评判、连续催促或统一标准驱动用户。
- 用户关闭 Agent 后，产品恢复为完整可用的本地记录工具。

## 12. 数据、隐私与本地优先要求

### 12.1 默认边界

- 本地副本是个人记录的权威来源。
- 核心记录、浏览、搜索、编辑、删除、备份和离线不依赖账号、API Key 或网络。
- AI 是否本地运行、是否调用远端模型，必须在 LN-007 架构与隐私评审中单独决定。
- 任何数据离开设备前，必须展示数据范围、目的、服务方、保留时间、费用和删除方式。
- 不默认将原始日记用于训练、群体拟合或社交匹配。

### 12.2 可逆性

- 原始 Log 只由用户显式编辑或删除。
- AI 派生数据可以单独导出、删除、重算。
- 删除原始 Log 后，引用它的观察和实验结论必须失效或重新计算。
- 恢复旧备份时不能留下与来源不一致的派生结论。
- 外部动作必须记录执行结果；撤销不可行时必须在执行前明确提示。

### 12.3 备份契约

未来备份需覆盖：

- Raw Log 与附件引用。
- 用户标签、目标和约束。
- 派生语义和观察及其来源。
- 实验、授权、执行和结果。
- Agent 配置、权限与审计。

Readable Markdown 继续服务阅读和归档；完整版本化备份服务恢复。两者语义不得混淆。

## 13. 成功指标

### 13.1 当前北极星保持不变

在 AI 价值被验证前，北极星仍是 **连续有用记录周**：至少 5 个真实记录日，并能在 60 秒内找回一条对后续行动或判断有用的记录。

### 13.2 下一阶段核心指标

| 指标 | 定义 | 初期使用方式 |
| --- | --- | --- |
| 观察准确率 | 用户认为准确且有来源支持的观察 / 已评价观察 | 少于 10 条只作学习证据 |
| 观察可用率 | 用户认为改变了理解或下一步的观察 / 已评价观察 | 不以生成数量替代价值 |
| 实验接受率 | 用户主动接受的实验 / 被展示的实验 | 拒绝原因单独记录 |
| 实验完成率 | 完成结果回顾的实验 / 已到期实验 | 未执行与中途退出分开 |
| 个人有效率 | 用户判断有效且代价可接受的实验 / 已完成实验 | 至少 5 个实验后再谈比例 |
| 自主感 | 用户是否更理解和掌控自身系统 | 防止 Agent 制造依赖 |

### 13.3 反指标

- 快速记录步骤增加。
- 首页永久控件或默认弹窗增加。
- AI 误改原文、错误结论无法追溯。
- 用户因整理负担降低真实记录频率。
- 建议很多但实验完成和结果判断很少。
- 自动执行造成不可撤销外部影响。
- 用户感到被评分、被控制或被持续催促。

## 14. MVP 验证方案

### 14.1 第一验证问题

> AI 能否在不增加记录负担、不改动原文的前提下，帮助用户从 14 天 Log 中找到一个准确、有用并值得验证的关键变量？

### 14.2 最小范围

1. 沿用现有本地记录和备份体系。
2. 用户维护少量已有标签。
3. 用户主动对最近 14 天记录执行一次分析。
4. AI 最多为每条记录匹配 3 个已有标签。
5. 生成一个带引用的当前轨迹观察。
6. 提出一个 3–7 天微型实验。
7. 用户接受、修改或拒绝。
8. 到期后记录结果、成本和主观判断。

不包含多 Agent 自动执行、第三方连接器、远端同步、群体曲线和社交匹配。

### 14.3 通过标准

- 核心记录路径步骤不增加，离线时仍完整可用。
- 原始记录逐字保持，所有 AI 结果均为派生数据。
- 用户能查看每条观察的来源并撤销/删除/重算。
- 至少完成一次 14 天轨迹生成和一次 3–7 天实验回顾。
- 用户认为观察准确、实验可执行，并能说出至少一个具体用途。
- 完整备份恢复后，来源、观察、实验和结果关系不损坏。

### 14.4 失败与退出条件

若出现以下情况，AI 闭环继续隔离或被移除：

- 用户为获得分析被迫增加日常记录字段或步骤。
- 观察缺少来源、频繁错误或只能生成常识性总结。
- 用户不愿发起或完成微型实验。
- AI 结果破坏离线可靠性、备份兼容或数据安全。
- 远端成本、隐私风险或维护成本明显高于已验证价值。

## 15. 分阶段路线图

### Phase 0：记录基线（当前）

- 完成 14 天真实使用验证。
- 维持快速记录、检索、备份恢复和离线可靠性。
- 不把远期愿景伪装为已实现能力。

### Phase 1：语义编译

- 完成 LN-007 AI/本地优先架构边界评审。
- 完成 LN-008 派生数据与反馈闭环模型。
- 实现 LN-009 已有标签匹配 MVP。

### Phase 2：个人反馈闭环

- 实现 LN-010 阶段回顾与 3–7 天微型实验。
- 完成 LN-014 的 14 天当前轨迹验证。
- 优先使用用户自己的历史记录作为参考。

### Phase 3：多 Agent 只读协作

- 先上线一个领域 Agent，再引入第二个领域。
- 验证主 Agent 是否真的能解决跨领域冲突，而非重复总结。
- 所有 Agent 默认只读，无外部执行。

### Phase 4：受控执行

- 建立权限中心、审计、预算、暂停和撤销。
- 从提醒或日程草稿开始，不直接进入自主操作。
- 按领域逐项放开有限自动化。

### Phase 5：参考曲线网络

- 先验证个人历史最佳曲线。
- 再评估匿名群体参考和领先轨迹匹配。
- 社交和 Dating 必须另行完成隐私、安全与反滥用评审。

## 16. 当前不做

- 不把 Log Note 改造成通用待办、日历或项目管理工具。
- 不要求每次记录都选择领域、标签、目标、时长或情绪。
- 不在首页并列展示所有 Agent。
- 不自动重写、润色或结构化用户原文。
- 不用一个分数评价用户的人生、自律或健康。
- 不依据少量数据生成诊断、人格判断或确定性预测。
- 不在闭环价值验证前开发完整多 Agent 执行平台。
- 不在个人曲线可信前开发 Dating 或跨用户关系匹配。

## 17. 上线前必须完成的专项评审

任何 AI、Agent、同步或外部执行能力进入主线前，都必须分别完成：

1. **产品评审**：改善哪个核心行为，用户证据是什么，默认界面成本是多少。
2. **架构评审**：本地/远端边界、模型供应商、离线降级、重算与删除语义。
3. **隐私评审**：数据范围、敏感级别、同意、保留、训练、共享和退出机制。
4. **安全评审**：提示注入、越权、凭据、外部写操作、审计和紧急停止。
5. **备份评审**：版本迁移、旧备份兼容、恢复事务和附件一致性。
6. **实验评审**：成功指标、观察窗口、失败条件和移除路径。

## 18. 待讨论决策

以下问题不阻塞 PRD v0.1，但会阻塞具体实现：

1. 首个领域 Agent 应优先选择时间、健康、学习还是工作？当前建议从 **时间 Agent** 开始，因为它最接近柳比歇夫日记，也最容易跨领域提供共同尺度。
2. 首个 AI 模式采用本地模型、用户自带 Key，还是经过明确同意的托管服务？
3. Universal Log 是扩展现有 `entry`，还是以兼容层保留 `entry` 并新增事件模型？
4. 用户目标与约束如何录入，才能不增加日常记录负担？
5. Agent Center 是独立页面，还是阶段回顾内的渐进入口？
6. 第一版时间记录采用即时计时、事后补记，还是两者同时支持？
7. 曲线的首个展示形态应是时间序列、阶段叙事，还是“事实—关联—实验”卡片？当前建议优先卡片与时间序列组合，避免抽象总分。
8. 在没有足够数据时，系统应如何明确表达“暂时不知道”？

## 19. 对外叙事基线

### 核心叙事

> 你每天都在产生关于时间、行动、状态与结果的 Log，但它们散落在不同工具里，也很少真正反过来帮助你。Log Note 用一套 Universal Log 保存真实轨迹，让 AI 理解，让多个 Agent 协作，再通过一次次可验证的小调整，逐渐找到更适合你的优秀曲线。

### 宣传图信息层级

1. **主标题**：Log Note｜个人 Agent OS
2. **主张**：把人生运行成可理解、可验证、可持续优化的 Log。
3. **核心链路**：Universal Log → AI 分析 → 多 Agent 协作 → 优秀轨迹
4. **可信边界**：本地优先 / 原文不改 / 授权执行 / 结果验证
5. **状态声明**：当前 MVP 已完成本地记录底座；AI 与多 Agent 为下一阶段方向。
