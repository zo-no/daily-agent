# LN-047｜月历内本地日计划产品准入

## 核心循环贡献

本能力不改变“快速记录”步骤，而是在月历次级表面提供计划时间线，作为后续“计划 → 实际 → 拟合”的计划输入层。月历仍保留按日期找回记录的入口。

## 用户证据

产品所有者明确要求今日时间线采用 Google Calendar 式单日纵向时间网格，并希望未来连接 Google Calendar，以便把计划时间线与 Log Note 的实际记录拟合。参考截图确认了小时轴、全天计划区、时间块和浮动新增的目标交互。

## 默认界面成本

- 首页快速记录 CTA、打开记录和保存步骤不变。
- 日计划只出现在月历内部，通过“月概览 / 日计划”切换进入。
- 日计划进入后成为顶栏以下的完整时间画布：使用紧凑日期导航、内部滚动小时轴和始终可见的新增计划按钮，不叠加记录页大日期或记录导出浮钮。
- 不增加默认弹窗、记录必填字段或首页常驻 Agent 控件。

## 离线、隐私、可逆与备份

- 第一阶段计划时间块完全本地保存，不需要账号、API Key 或网络。
- 计划与原始记录分开保存；创建、编辑和删除计划不改写记录正文。
- 完整 JSON 和便携备份包含计划时间块；Markdown 与结构 JSON 不包含计划。
- Google OAuth、远端事件和双向同步不在本项范围，后续需独立架构与隐私评审。

## 验证与移除

- 纯函数测试覆盖时间解析、15 分钟吸附、时间范围校验、旧备份迁移和完整备份往返。
- 移动端验证月概览进入日计划、空白时段带入时间、浮钮创建、编辑、删除、返回记录视图和离线恢复。
- 交互变化运行 `npm run check`、`npm run design:check`，并用 320/390/1280 非 fullPage viewport 截图与 DOM 边界断言证明页面不滚动、小时轴内部滚动、计划浮钮完整可见。
- 计划数据位于独立 `planBlocks` 数组；移除界面时不影响 entries，必要时可单独导出后删除。

## 失败或保持隔离条件

- 用户很少创建计划时间块，或创建计划明显降低真实记录频率。
- 日计划抢占首页快速记录主路径。
- 用户把计划误认为已经同步到 Google Calendar。
- 计划数据导致旧备份恢复、离线持久化或移动端质量门禁退化。
