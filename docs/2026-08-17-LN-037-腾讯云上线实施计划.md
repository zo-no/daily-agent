## 发布架构

```text
浏览器
  ↓ HTTPS
note.kual-shown.online
  ↓ A 记录
81.70.8.30:443
  ↓ Nginx（独立 server_name）
127.0.0.1:3100
  ↓ systemd: log-note.service
/opt/log-note/current
  ├─ Supabase Auth / Postgres
  └─ Google OAuth / Calendar API
```

COS 不在首发链路中。当前图片继续先存账号隔离的 IndexedDB，并由 `.lnbackup` 完整备份。COS 图片同步在首发稳定后单独准入、实现和验证。

## 生产目录与回滚

```text
/opt/log-note/
├─ releases/<release-id>/
├─ current -> releases/<release-id>
├─ shared/.env.production
└─ incoming/
```

- 每次发布创建新 release 目录，不在 `current` 中原地覆盖。
- 新 release 完成 `npm ci`、`npm run build` 和本机健康检查后，才切换 `current` 软链接。
- `log-note.service` 固定监听 `127.0.0.1:3100`，腾讯云安全组不开放 3100。
- 回滚只切回上一个 release 软链接并重启服务；数据库 migration 必须向前兼容，不依赖破坏性回滚。
- 生产 Node 使用独立 Node 22 运行时，避免升级服务器全局 Node 18 后影响现有服务。

## 停止条件

- migration dry-run 与远端历史不一致；
- 任何账号隔离、CAS、备份恢复或离线门禁失败；
- 新 Nginx 配置影响现有服务；
- 域名未备案或 HTTPS/OAuth 回调未正确生效；
- 发布物无法由明确 commit 重建。

遇到以上任一条件立即停止发布，保留当前生产版本，不通过临时跳过测试继续上线。
