# LN-036｜账号密码、账号隔离缓存与自动云端保存方案

## Phase 2 决策

用户已将产品方向收敛为：**不登录无法使用 Log Note**。

- 邮箱密码或 Google 必须先通过 Supabase Auth，获得可信 `auth.uid()`。
- 每个账号拥有独立的浏览器文字缓存、同步元数据和本地图片命名空间。
- 修改先写本地缓存，再自动 debounce 保存到 Supabase；网络不能阻塞当前编辑。
- 新设备必须联网认证并加载一次；已经认证且有该账号缓存的设备可以离线继续使用。
- 不实现 Obsidian 式重型三方合并。revision 不一致时停止覆盖，由用户选择云端或本机版本。

浏览器随机 ID 不能通过 Supabase RLS，也不能升级成数据库账号。密码只交给 Supabase Auth；Log Note 不把密码写入 `localStorage`、记录 JSON、备份、日志或数据库文档。

## 数据归属与首次进入

文字缓存键为 `log-note:data:user:<auth.uid()>:v1`，同步元数据键为 `log-note:sync:user:<auth.uid()>:v1`。图片仍存于 IndexedDB，但每条 Blob 记录带账号 owner；读取、容量、清理、删除和恢复均只作用于当前账号。

首次登录的处理顺序：

1. 若账号已有云端文档且设备没有该账号缓存，直接校验并使用云端文档。
2. 若云端为空、设备存在旧匿名数据，展示明确选择：把旧数据作为此账号初始数据，或为此账号重新开始。
3. 无论选择哪项，旧匿名 payload 都保留，不删除、不静默上传。
4. 若设备缓存与云端都存在，只有同步元数据能证明共同 revision 时才自动继续；无法证明时进入冲突，不做 last-write-wins。

## 云端范围

迁移文件按顺序执行：

1. `supabase/migrations/20260816090000_log_note_documents.sql`
2. `supabase/migrations/20260816170000_require_expected_revision.sql`

第二个迁移是已执行初版后的安全纠正：已有文档必须提供明确 expected revision，`NULL` 不得绕过 CAS。

- `log_note_documents`：每个 `auth.uid()` 一份当前完整文字文档。
- `log_note_document_revisions`：保留最近 30 次已接受版本。
- `save_log_note_document`：原子创建或 compare-and-swap 更新；operation ID 保证重试幂等。
- 两张表强制 RLS；authenticated 只能读取自己的行，写入经函数再次核对 `auth.uid()`。

云端 JSON 包含记录正文、领域、分类、模板、Markdown 设置和日计划。图片 Blob 和图片引用都从云端 payload 中移除，避免新设备出现伪完整的缺图记录。图片只在本机和便携 `.lnbackup` 中。

浏览器只使用 project URL、publishable key 和用户 session；service-role、数据库密码、Google Client Secret 禁止进入客户端。

## 自动保存与冲突

- 每次本地成功修改后进入等待保存，约 1.2 秒 debounce 后上传。
- 上传携带当前云端 revision；成功后记录新 revision 和已同步文字 fingerprint。
- 保存期间再次编辑时，当前请求完成后继续保存新状态。
- 断网或暂时错误只改变同步状态，本地记录保持可用；恢复网络后先重新读取并 reconciliation，不在未知 revision 下直接写。
- 同一待保存快照复用 operation ID；若服务端已提交但响应丢失，读回相同 fingerprint 后视为已同步，不制造假冲突。
- fingerprint 使用稳定键序与固定长度摘要，不在同步元数据中复制整份记录。
- 自动采用云端文字时，仍存在的同 ID 记录保留本机图片引用；云端继续不保存图片 Blob。
- 云端 revision 变化且本机也有未同步修改时进入冲突，停止后续自动写入。
- “使用云端”前下载完整本地 `.lnbackup` 回滚文件；“保留本机”是用户明确确认后以最新 revision 发起的新写入。
- 不按客户端时间判断谁更新，不自动拼接两个 JSON，不静默覆盖。

## 登出与切换账号

退出只锁住应用并清除 Supabase 当前浏览器会话，不删除本地或云端数据。另一个账号登录后只加载自己的缓存、同步元数据和图片；不能看到、上传或清理上一个账号的数据。

## 隐私边界

RLS 隔离普通账号，但数据库服务端仍可处理明文日记；这不是端到端加密。产品不得宣称“服务商也无法读取”。若未来需要该承诺，必须另做客户端加密、密钥恢复和多设备密钥分发评审。

## 自动化证据

- 116/116 单元测试：账号缓存键、固定长度稳定 fingerprint、保守 reconciliation、图片引用合并、NULL CAS 纠正 migration、云端 payload、认证安全及原有数据模型。
- 21/21 浏览器场景：未登录全路由门禁、44px+ 登录操作、记录/计划/结构/恢复/附件原有主链路。
- PWA：生产构建、安装条件、已认证账号离线缓存、持久化、更新与缓存安全。
- `git diff --check` 通过。

## 仍需真实会话验收

- 邮箱注册/确认/登录、Google 同浏览器回调和退出。
- 空账号第一次编辑自动创建 revision 1。
- 第二设备登录同账号读取云端文档。
- 两设备制造 stale revision，确认客户端停写且选择前双方数据不变。
- 两个真实用户交叉读取、函数写入与历史读取均被 RLS 拒绝。

初始 SQL migration 已在目标 Supabase 项目执行；匿名读取两张表和匿名调用保存函数均返回 401。安全纠正 migration `20260816170000_require_expected_revision.sql` 仍需在目标项目执行后，再做真实账号同步验收。当前未部署。
