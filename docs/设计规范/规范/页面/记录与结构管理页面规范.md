# 记录与结构管理页面规范

## 记录页

- MUST 在时间与分类记录视图中以当前日期和记录内容作为首要信息；移动端唯一日记/计划拨杆位于下方快速操作区，导出与新增记录必须在其下方或相邻语境内横向并列固定可达，导出左、蓝色新增记录右，并显示“导出今日日记”；日计划模式隐藏日记导出/新增记录，只保留下方工作区拨杆和其上下文内、与同一轨道共轴的新增计划操作。
- MAY 只在移动端当前领域目录项下方显示一个独立的领域复盘入口，并让领域文字与入口在书脊右侧组成同一竖列，不得为当前领域在左侧阅读面额外占位。移动端顶部工具、两个拨杆、所有领域目录按钮及可见文字（无论是否显示复盘入口）和复盘按钮 MUST 共用距右侧 `28px` 的操作轴；领域目录按钮与复盘按钮的真实目标均为 `44px × 44px`，当前领域的两个目标保持至少 `4px` 竖向间距。目录按钮继续只负责滚动定位，其 `10–12px` 节点图形 MAY 伸出按钮左侧，但 MUST 共用距右侧 `56px` 的独立书脊轴。Diary Agent 的真实目标与操作列 MUST 保持至少 `4px` 水平间距，不得以不透明文字底遮盖碰撞。复盘入口 MUST 使用项目内真实透明石墨图标并包含领域名的可访问名称；入口随当前领域移动，不得复制到每个领域、改变顶部“搜索 → 设置 → 时间/分类”或下方唯一“日记/计划”拨杆的位置、覆盖正文或增加快速记录步骤。桌面 MAY 在页头提供一个弱于记录主动作的次级入口。详细页面行为见 [领域复盘页面规范](领域复盘页面规范.md)。
- MUST 区分线性记录和周期记录：前者按时间线展示，后者按模板节奏和值展示。
- MUST 让固定/周期记录优先在首页模块内完成：单值直接输入，结构化字段在当前条目下方展开；不得为可在当前上下文完成的填写强制打开弹窗。
- MUST 将首页固定/周期记录与普通记录置于同一开放纸面，不得使用卡片底色、圆角、阴影或完整外框。仅在存在普通记录时，时间记录使用唯一可见的“记录”Serif 区块标题、等宽时间列、每行独立的 `18px × 6px` 手绘短横与手绘弱行分隔；无普通记录日期 MUST 完整省略该标题与说明性空态，并让固定记录直接接续，不留无归属长线。固定记录按稳定领域分组，并使用“指标名 / 值”两列与手绘弱行分隔，但时间排序下不得把领域名再次显示成左侧标题。长分隔、短横与区块边界 MUST 来自透明栅格手绘资产，不得用笔直 CSS border 临摹；透明 `1px` border 仅可保留稳定几何。在 `320–700px`，固定记录行的手绘分隔必须左对齐并在行右缘前 `24px` 收笔，不得与 Diary Agent 图形直接相连；固定单值输入右缘 MAY 仅为避开 Agent 的 `44px` 真实目标再收 `4px`，但输入高度、值、焦点、保存行为、行布局和更宽视口不得改变。展开编辑器可在当前行下方建立明确交互边界，但不得把整个列表重新包成卡片。
- MUST 将每个固定记录领域的完成数与管理入口视为同一辅助工具簇：完成数使用 `12px` 等宽数字、`500` 字重和弱色，“调整”使用 `14px`、`500` 字重；二者同一行紧邻排列，并在时间排序下独立右对齐而不依赖可见领域标题。“调整”的可见文字可以克制，但触控与键盘焦点区域不得小于 `44px`，不得用胶囊、粗边框或高饱和底色把该工具簇提升为第二标题。
- MUST_NOT 在首页时间记录或固定记录上显示领域/分类归属胶囊。时间记录须保留等效隐藏无障碍文本，固定记录须保留隐藏领域标题供区块语义与右侧目录使用；用户主动写入的 `#标签` 继续用低饱和蓝色胶囊显示并明显弱于 `16px` 记录正文。移除视觉归属不得改变记录的 `categoryId`、标签、搜索或导出语义。
- MUST 让时间记录行与固定记录行的聚焦状态覆盖完整所属行：使用透明蓝色手绘圈线从左向右显露，不得只框住输入框或让原生硬矩形与圈线叠加。圈线不得改变布局、遮挡文本或截断 `44px` 输入命中区；键盘焦点与 `focus-within` 语义必须保留，reduced-motion 下直接显示最终圈线。
- MUST 让固定记录位于当天时间线或分类分组内容之后；空时间线不得用视口最小高度或大块空状态制造无意义留白。
- MUST 在窄屏与宽屏都保持“快速新增 → 当天内容 → 固定记录”的阅读顺序，不得形成卡片墙或横向滚动。
- MUST 将 `600–700px` 视为宽移动工作区并继续使用完整右轨，将 `701–800px` 视为紧凑桌面/平板工作区并隐藏移动笔画；两档均限制时间线与固定记录为可扫描阅读簇，不得把手机端的整宽值列和放大标题直接拉伸。
- MUST 让新增记录默认进入最短填写路径，不在首屏要求维护领域或分类结构。
- MUST 让普通记录编辑器表现为从当前日记抬起的一张纸页，而不是独立的通用蓝色弹窗：使用同源本地纸张纹理、温暖不透明纸面、克制遮罩、`8–10px` 顶角、Serif 标题和可扩展的主书写区。移动端纸页高度 SHOULD 占可视高度约 `72–78%`，工具栏贴近纸页底部但不得覆盖正文；`Done` 使用深蓝细描边和功能性 `5–7px` 圆角，不得变成高饱和胶囊。关闭与完成目标继续不少于 `44px`，正文输入继续不少于 `16px`，可选结构和附件控件保持次级。打开编辑器仍只需一次操作，普通文本输入后保存仍只需一次 `Done`，不得修改保存内容、Markdown、附件、账号、同步或备份语义。
- MUST 将普通记录编辑器的“更多”实现为带 `aria-expanded` 与稳定受控区域的披露控件。折叠态继续让书写纸页占主导；展开态在移动端保留不少于 `160px` 的可编辑正文，但正文区 SHOULD 收敛到约 `184–236px`，随后依次呈现紧凑的日期/时间与分类/标签账页、带弱顶边界的附件区、仅既有记录可见的危险页脚。删除不得与常规字段同组；其确认和回调不得改变。`320–350px` 日期与时间 MUST 纵排，其他目标宽度不得出现原生日期/时间控件裁切或横向溢出。正文聚焦使用页边细蓝墨线，不得出现覆盖整块写作面的硬矩形；所有按钮、输入与选择器保持可见键盘焦点和不少于 `44px` 的目标。
- MAY 仅在普通自由文本编辑器的书写纸页内挂载现有本地 Hero 形象，作为一个真实命中区不少于 `44px` 的内容优化入口。页面外层的 Diary Agent traveler 在编辑器打开时继续隐藏，不得与 composer-local Hero 重叠。Hero 只看护当前文本：空正文点击不得发起请求；非空正文每次点击最多发起一次有界请求，不得展开对话、追问输入、历史、弹层或独立卡片。候选稿 MUST 复用原书写区，并只用一行紧凑操作提供“看原文 / 看优化稿”、“使用优化稿”和“取消”；所有真实目标不少于 `44px`。只有用户显式使用候选稿才可更新当前草稿，且仍需原有 `Done` 才能保存；取消、关闭、正文/目标/账号变化、迟到响应、离线或错误均为零写入。结构化与周期编辑器不得显示该入口。
- MUST 让首页空日和有记录日共享同一阅读起点：日期上下文之后只出现真实存在的普通记录、Agent 区间或固定台账；不得用最小视口高度、伪空态或装饰模块填补空白。有记录时 `Record`、记录行、Agent 与固定台账按正文顺序使用明确的区块间距；无记录时固定台账直接成为第一内容区。移动装订沟槽不得覆盖这些内容或 44px 命中区。
- MAY 在当天存在普通记录且处于日记模式时显示一个次级 Agent 插图。桌面闲置态可在插图附近直接说明“点击唤醒”；移动端 MUST 使用默认透明石墨线条精灵，并让 `idle/scanning/reviewing/complete` 四态通过内部 `appearance role → state → local asset` 契约解析独立本地姿态。普通记录结束到固定记录开始之间的纸面区与相邻约 `56px` 装订沟槽是唯一活动区：闲置从装订边探头，扫描可在区内巡游，审查在右半区保持可见且避开行内批注与右侧操作，完成回到装订边；不得在左侧阅读面另放说明块。移动端仍须通过不少于 `44px` 的真实按钮、明确可访问名称和可见插图表达入口；未知角色或状态回退到默认闲置形象，本阶段不得增加选择器、上传、设置字段、持久化、网络或备份语义。激活后 MUST 留在当前日期页面，并把问题、会话与确认动作直接放在对应普通记录行下方；不得打开全屏弹窗、全局聊天抽屉或强制跳往独立整理页。扫描、发现问题、分类与完成 MUST 在同一纸页几何中表达：日期标题下方显示弱状态摘要；进入具体问题后 MUST 切换到 `reviewing` 姿态并保持活动区，不得隐藏形象、折叠形象槽、绘制蓝色路径、虚线或长下划线。来源关系由紧邻记录的批注、`aria-current` 与一个不跨越正文的短局部笔触表达；完整蓝色手绘环只保留给真实键盘焦点，不得再用于 Agent 活动态。活动记录与行内批注 MUST 形成一个连续纸面区块：活动记录原有的行分隔线隐藏，批注以留白结束且不得画闭合底线，批注下方邻近的固定记录区块也不得再重复画一条顶部线。行内区域 MUST 表现为紧凑页边批注：移动端批注阅读轴与来源记录真实 `.entry-content` 文字左缘对齐，而不是只与带 padding 的 `.entry-body` 容器对齐，并在右轨前至少留出 `8px`。停止位于批注左上外侧，`当前 / 总数` 独立位于右上，两者不得贴合。来源记录继续使用 `16px` 全墨色 Sans 并承担页面主视觉；Agent 问题必须切换为 `14px` muted Serif / 宋体回退的页边批注角色，不得继续使用与正文相同的 Sans 正文角色；分类结果使用 `13px/600` Sans，动作与回复占位使用 `12px` 弱色。真实移动输入仍 MUST 不小于 `16px`，不得通过缩小 textarea 规避层级问题。分类到回复使用 `4–8px`，回复到动作使用 `4px`，动作到底部下一条记录使用 `12–16px` 小组间距。只允许短角标或局部刻度连接问题、弱提示与单行回复，不得使用贯穿对话与动作的高大三边括号。输入不得使用长横线，只允许短蓝色光标笔触；空输入不得显示禁用的发送动作。内容追问在用户回答前只显示单行回复与“保持原文”，产生建议内容后才显示“补充到原记录 / 作为新记录”。移动端行内动作 MUST 放在一个共享 `1px` 弱边界与 `5–7px` 外圆角的紧凑分段操作组内，每个真实动作至少 `44px`，组内只使用细分隔线和克制的主动作浅色/低饱和文字强调；不得再堆叠多个独立全宽蓝底或描边按钮。长文字允许在组内换行或按两列后跨列，不得压缩可读性。进度与停止动作降为弱信息，不得堆成高大的聊天框或表单。Agent 一次只能锚定一个真实 `entry.id`。闲聊、追问和建议均为会话期状态；只有用户另行选择“补充到原记录”“作为新记录”“应用分类”时才可写入，保持原文不得产生写入。分类只能选择已有领域/分类且只改 `categoryId`，并提供撤销；不得创建结构、标签或静默修改正文。日期切换、月历、搜索、设置、计划或离开页面 MUST 取消会话。关闭月历时日期上下文到首个内容区只保留 `24px` 区块间距；顶部搜索、日历与设置在移动端继续使用透明手绘 icon-only 控件，底部导出复用下载图形并显示本地化同日范围标签；可见图形与命中中心不得覆盖装订线，保留可访问名称、焦点/激活状态与不少于 `44px` 的命中区，且不得露出双圈印章。对话展开不得改变右轨 X 轴、Plan Agent、快速新增步骤或备份格式。
- MUST 按 LN-076 Rework 8 只替换上一条的 Agent 外层定位、空日可见性与形象运动范围：Diary 的空日和有记录日都在应用外壳级固定层显示角色；移动 `320–700px` 沿视口右侧安全书脊段上下巡游，桌面静止探头，滚动不消失。移动素材必须延续既有石墨角色，并在每态 6 帧内提供可辨识但克制的姿势：idle 换握并让身体跟上，scanning 探出/收回，reviewing 保留手抵下巴的思考姿势并让眼睛在来源与批注间移动，complete 盘身、舒展并停稳；不得只把一张静图快速上下平移。Plan、搜索、设置和编辑器隐藏；月历展开时角色缩回并停止，不进入日期格。空日点击仅显示 4.5 秒页边批注，今天与其他日期使用不同文案，再次点击、Escape、超时、换日或换页面关闭，不得调用审查、创建记录或写入任何数据。已有记录日的唤醒、停止、行内批注、分类与显式写入语义保持不变。角色素材不含书脊线，按钮与图像同步移动并低于右轨真实控件层级。
- MUST 让移动端 Agent 行内批注重复使用两条稳定竖轴：问题、分类结果、回复文字与分段操作组左缘共享记录正文阅读轴；关闭符号中心、短角标中心与回复短蓝笔触中心共享批注沟槽轴。分类结果与问题之间使用 `4px` 配对间距，操作组右缘与会话右缘对齐。装饰笔触只能占用沟槽，不得再通过输入内缩把回复文字推离正文轴；真实触控区继续不少于 `44px`。
- MUST 将移动端 Diary Agent 表达为“来源记录的辅助批注”，不得再用另一套 Serif 正文或全宽分段控件制造第二主视觉。本条取代上两条中关于 `14px Serif`、左侧关闭/沟槽共轴、分类 `13px`、`4px` 固定配对间距、操作组左缘对齐正文及共享外边界的要求：来源记录保持 `16px` 全墨色 Sans；Agent 问题使用同一 Sans 阅读系统的 `13px` 支撑墨色，顶部使用 `10px` Mono `Agent` 角色标签和 `11px` 弱进度，分类结果、动作、回复占位均为 `12px`，真实 textarea 仍不小于 `16px`。问题、分类和回复文字 MUST 与真实 `.entry-content` 左缘误差不超过 `1px`；左侧只保留约 `2px × 24px` 的短来源标记，标记到阅读轴约 `12px`；关闭图标 MUST 位于右上，进度在其左侧且不得重叠。分类与问题使用约 `6px` 间距，分类到回复为 `2–8px`，回复到动作不超过 `4px`，动作到下一条记录为 `8–14px`。动作 MUST 采用无外框、无分段线、右对齐的紧凑文字目标，每个命中区仍不少于 `44px`；主动作仅用文字色强调，任何单项不得填满整条批注宽度。活动摘要 MUST 降为 `12px` 弱色文字与一个小蓝点。右侧 Search / Calendar / Settings / Export 图标带、记录正文轴、快速记录步骤与 Plan Agent 几何保持不变。
- MUST 在移动端 Agent 激活时消除由命中区和容器叠加产生的伪内容留白：关闭日期上下文到“记录”区只使用 `0–12px`，来源活动行在单行内容时使用约 `52px` 最小高度，时间/正文上下内边距同步收拢；一到两个未解决动作紧贴在完整回复输入下方并共用一条横行，不得与输入重叠或形成脱离内容的按钮带；三项解决动作在 390px 使用单个三列动作行，允许英文标签在各自目标内自然换行。Agent 的挂载区不得贡献可见高度；普通记录结束到固定记录工具簇之间只保留约 `12px` 的自然区块节奏，并由最后一条普通记录的手绘横线独占过渡，固定记录区不得再补画第二条顶部横线。所有按钮仍 MUST 不小于 `44px`，textarea 仍保持 `16px`，点击区不得覆盖相邻语义操作。此密度规则只作用于移动 Diary Agent，Plan Agent 与快速记录保持不变。

- MAY 在时间视图保留独立的固定记录填写区，以维持低摩擦记录路径；必须按稳定 `domainId` 分组，字段和值左对齐成两列开放行。真实领域名保留为隐藏区块标题并显示在右侧区块目录，不得在左侧重复成可见 Serif 标题。该展示差异不得改变记录的领域、分类或 Markdown 导出归属。
- MAY 在普通自由文本记录的二级详情中提供一张本地图片附件；默认编辑面不得新增必填步骤或常驻工具栏控件。
- MUST 将附件缺失、损坏或读取失败显示为不发起网络请求的占位，正文仍可编辑、保存、搜索和导出。

## 设置 → 记录结构

- MUST 使用一棵连续的领域 → 分类 → 模板层级树，不用标签页拆分管理上下文。
- MUST 让领域、分类和模板各自保持独立的名称、排序、归属和编辑能力，只合并管理界面，不合并数据概念。
- MUST 允许从设置第六项进入完整层级树，也允许从首页“调整固定记录”深链到同一面板的周期模板聚焦视图。
- MUST 将结构编辑留在 `/settings#record-setup`，将结构 JSON 与起步示例下载留在“下载 → 记录结构”；现有 `/settings#structure` 继续指向下载组，`/templates` 与 `?focus=periodic` 作为兼容跳转，不得复制文件动作。
- SHOULD 保持列表紧凑，管理动作不应让页面看起来像后台仪表盘。

## 设置页

- MUST 将设置页作为独立控制面，并按用户任务而不是技术对象组织。桌面使用稳定的左侧设置索引与单一活动面板；`760px` 及以下使用“完整设置索引 → 单一全宽详情”的两级移动导航，不得把分区藏在横向滚动 Tab 中。移动设置首页必须一次看全常规、账号、下载、恢复、图片、记录结构六项，只出现一个“设置”标题；详情页顶部返回动作回到设置索引。索引项和全部主要操作不得小于 `44px`，切换面板不得造成页面横向溢出。
- MUST 把所有产生文件的操作按亲密度合并到“下载”：今日/全部记录、下载格式、完整/文字备份、当前结构和起步示例在同一面板内分组；“记录结构”承载领域、分类、模板、字段与固定记录编辑；“恢复”独立承载导入、校验、确认与替换风险；“图片”只管理图片占用与清理；“常规”只保留语言与添加到主屏幕。一次只渲染一个一级任务，保留 `/settings#export`、`#backup`、`#structure`、`#storage` 与 `/settings#record-setup` 的职责和兼容映射。页面使用连续纸张、标题、留白和细分隔线表达层级，不得演变为设置卡片墙。
- MUST 删除或避免“选择设置”“记录保存在哪里”“本地使用”“保存在此设备”等重复、抽象或不准确的界面标题。移动索引副信息应展示当前语言、记录数、恢复动作、图片数/容量等不同状态，不得用四句结构相同的说明复述栏目名称。浏览器数据边界只在下载备份组和图片区各保留一次必要说明。
- MUST 对语言切换等结果显而易见的常规控件只保留名称、当前状态和操作，不再解释其作用；添加到主屏幕只保留一个可执行提示，不并列重复“效果说明 + 操作说明”。同组分隔线只允许出现在相邻设置项之间，首项上方和末项下方不得再画无归属的装饰线。
- MUST 将账号作为可选次级设置任务：以 Supabase 邮箱密码作为国内网络下的主要账号路径，以 Google 作为替代路径；不得用浏览器随机 ID 冒充可访问数据库的本地账号。“无账号使用”通过直接返回记录页表达，不需要创建本地身份或密码。不得把账号变为首次启动、记录、浏览、搜索、编辑、备份恢复或离线使用的前置条件。邮箱密码表单 MUST 使用明确标签、密码遮罩、至少 8 位校验、登录/注册熟悉切换和不少于 `44px` 的操作；密码只能交给 Supabase Auth，不得写入本地 state、日志、数据库文档或备份。登录后 MAY 展示独立的云端保存组，但登录本身不得上传；保存必须明确列出文字记录、日计划、结构和设置，并明确图片仍在本机。覆盖云端或本机前必须确认，云端恢复前必须下载完整便携回滚备份；revision 变化必须停止覆盖。不得加载远程头像，不得把 OAuth code、token、session、user ID、workspace 或 revision 写入 Log Note JSON/便携备份或 Service Worker 缓存。缺配置、拒绝授权、过期、离线与服务失败均不得改变本地记录状态；退出失败时必须保留真实登录状态并明确提示，不得虚假显示已退出。
- MUST 让下载页主阅读顺序固定为“记录 → 备份 → 记录结构”，三组使用 `18px` 小标题、`4px` 标题说明间距和 `32px` 跨组间距。Markdown 下载格式必须作为记录组内的内缩渐进设置，不得形成第四个等权区块；浏览器记录/图片数量使用 `12px` 等宽元信息并紧邻“备份”标题，换设备提示使用下一行 `14px` 说明；“推荐”必须贴近“完整备份”名称，不得漂移到行尾成为独立状态列。
- MUST 明确便携备份包含记录、结构与本地图片，是存在图片时的推荐完整备份；JSON 备份只包含文字状态与图片引用，不得暗示包含图片文件。导出与“恢复并替换”必须分组，恢复区常驻说明替换范围与 JSON 图片影响，并继续在完整校验后请求确认。
- MAY 在“恢复”页的替换操作之前提供独立的“导入日记 Markdown”合并组。该组 MUST 明确不替换当前数据，只接受文件名携带有效日期的 Markdown，将正文作为普通记录在浏览器本地解析并加入当前账号；MUST 按日期、时间与正文精确去重，重复导入保持幂等，失败或无有效记录时不得写入。合并组不得复用替换备份的风险色或警告边界；替换备份仍需使用独立标题、说明与警告表达更高风险。解析能力 MAY 被未来 CLI/MCP 复用，但外部入口不得绕过账号隔离缓存与 revision 冲突保护。
- MUST 在本地 payload 损坏或迁移失败时进入可见恢复模式：普通 Markdown、JSON、便携与当前结构导出及设置编辑必须暂停，记录结构编辑器不得挂载或触发空模板清理，临时默认 state 不得被描述或导出为真实档案；浏览器确实返回原始 payload 时，用户必须能逐字下载；若存储读取在取得原值前失败，则必须明确说明无法生成恢复文件，禁止导出伪造内容。两种状态都须继续允许从有效 JSON 或便携备份恢复，且恢复成功后才解除保护。
- MUST 为 JSON 文件设置读取前体积上限；取消、超限、损坏、校验失败或本地持久化失败均不得改变当前 state 或附件 Blob。清理图片只能移除当前已持久化 state 未引用的 Blob，在恢复保护期间必须禁用。
- SHOULD 将 Markdown 格式作为导出领域内的渐进展开高级设置，桌面可使用字段与 sticky 预览双栏，中窄屏改为单栏；预览必须有可访问区域名称，恢复默认保持次级视觉。
- MUST 保持中英文切换只改变界面语言，不翻译或改写记录；本地存储和安装说明不得暗示自动同步。账号页只有在真实登录且数据库可用时才可显示云端版本，文字云端保存不得冒充图片完整备份。

## 数据边界

- 活跃工作副本 MUST 继续使用版本化 JSON 与浏览器 `localStorage` 保存文字和结构；获准的本地图片二进制 MUST 独立保存在 IndexedDB，不得写成 data URL 或 base64 状态。已登录用户 MAY 显式保存带 revision 的文字快照到受 RLS 保护的 Postgres；登录不得自动上传，CAS 冲突不得 last-write-wins，图片未进入私有 Storage 前必须从云端 payload 移除引用并显示真实限制。
- MUST 提供文字/结构 JSON、带附件校验的便携备份、结构 JSON 和 Markdown 导出。
- MUST_NOT 因视觉或排序改造修改已有日记正文。
- MUST_NOT 自动上传附件、默认加载远程图片，或让图片失败阻止文字记录保存。
