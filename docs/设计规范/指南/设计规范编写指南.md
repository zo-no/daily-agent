# 设计规范编写指南

## 新增规范前

1. 在 `index.md` 中确认是否已经存在主要维护入口。
2. 判断内容是正式规则、写作方法还是调研证据。
3. 正式规则复制 `模板/Design 规范模板.md`，并填写元信息。

## 正式规则写法

- 用 MUST、MUST_NOT、SHOULD、SHOULD_NOT、MAY 表达强度。
- 每条规则描述可观察的产品行为，不描述个人审美偏好。
- 阈值必须给出单位和适用情境，例如“触摸拖拽延迟约 180ms”。
- 页面规范引用组件规范，避免复制同一规则正文。
- 每份规范必须包含可操作的验收或 Review 检查表。

## 修改流程

1. 更新规则正文和 `updated` 日期。
2. 检查 `DESIGN.md` 是否需要同步简明事实。
3. 更新 `index.md` 路由（仅在入口变化时）。
4. 运行 `npm run design:check`、相关测试和浏览器 QA。
