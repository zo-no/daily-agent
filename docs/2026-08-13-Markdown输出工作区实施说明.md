# Markdown 输出工作区实施说明

## 用户问题

设置页已经提供 Markdown、完整备份和结构导出，但记录结构页又通过“导出记录”抽屉完整复制了五项下载。两套入口内容相同，且模板页中的 Markdown 下载无法就地调整格式，造成重复页面与不清楚的维护位置。

## 本轮收口

1. `/settings#export` 成为唯一 Markdown 输出工作区：先导出今天或全部 Markdown，再编辑既有格式字段，并在旁边查看当前日实时预览。
2. 完整 JSON 导出和恢复独立为“备份与恢复”分组；恢复仍先校验、再确认替换，无效文件不改动当前数据。
3. `/settings#structure` 独立提供当前结构 JSON 和通用 JSON 示例；模板页页头“导出选项”直接链接到该锚点。
4. 删除模板页重复的“导出记录”抽屉、五项下载和对应序列化状态，不保留第二套清单。
5. 首页当前日 Markdown 快捷下载保持原位置、原步骤和原行为。

## 视觉与移动端

- 页面继续使用共用管理页宽度、字体和纸张色，不新增卡片墙或装饰性渐变。
- 下载动作去掉尾部 chevron 和蓝底方形图标块；分隔线只用于 section 边界及必要的组内起点。
- 桌面端格式字段与预览相邻，移动端按导出、格式、预览的自然顺序堆叠。
- 移动端 Markdown 输入和选择器使用至少 16px 字号，所有下载、恢复和链接入口保持至少 44px 触控目标。
- `#structure` 使用滚动留白，直接进入锚点时标题不会贴住或被页面顶部遮挡。

## 数据与兼容边界

- 未修改 `markdownSettings` 的字段、默认值、迁移或即时持久化方式。
- 空字符串仍是合法格式值，不会被界面校验自动补回默认值。
- Markdown 继续由 `markdownForDate` 和 `markdownForAll` 生成，下载文本契约不变。
- 完整备份、恢复覆盖语义、结构导出不含 `entries` 以及通用示例内容均继续复用既有数据函数。
- 未修改首页记录步骤、固定记录业务、结构树业务或数据 schema。

## 回归证据范围

- 单元测试：Markdown 空字符串设置在完整备份恢复后保持逐字输出。
- 移动端 E2E：模板页不存在重复导出抽屉或下载按钮；“导出选项”直达 `/settings#structure`；锚点位置、即时预览、恢复安全、下载内容、输入字号、触控目标和横向滚动通过验证。
- 真实运行：320、390、1280 三个视口复核设置页和模板页入口，并保存截图到 `output/playwright/`。
