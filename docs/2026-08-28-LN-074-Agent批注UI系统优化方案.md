# LN-074 Agent 批注 UI 系统优化方案

## 改善的核心行为

本轮优化服务于“浏览 → 判断 → 编辑/保留”的日记审查路径。目标不是新增 Agent 能力，而是让用户在手机上能更快看清：哪条原始记录是主信息、Agent 正在问什么、建议归到哪里、下一步可以做什么。普通快速记录的打开、输入和保存步骤不增加。

## 输入与参考

- 用户提供的 390px 截图显示：时间记录、Agent 批注、右侧装订轨、固定记录同时出现，是当前最容易暴露层级问题的真实组合。
- 已调用 `design-review` 和 `frontend-skill` 的审查方法：用产品工作台而不是营销页思路处理，优先修正信息层级、阅读轴、密度、触控目标和状态反馈。
- 已按 `citadel` skill 尝试读取 `https://km.sankuai.com/collabpage/2782913331`，当前本机 SSO/CIBA 读取失败，无法可靠引用该学城文档原文。本文因此不冒充已读取内容，只采用仓库现有规范和截图证据。

## 截图诊断

1. 原始记录、Agent 问题、分类标签和固定记录输入都接近正文权重，用户需要多看一眼才知道谁是主内容。
2. Agent 的 `Agent`、`1 / 4`、关闭按钮和问题文本分散在不同视觉角落，像几个独立控件，而不是同一条批注。
3. 分类结果虽然只出现一次，但蓝色标签和蓝色动作距离太近，容易让“结果”和“动作”在扫描时混成一层。
4. 右侧装订轨已经承担页面导航，Agent 批注不能再靠额外边框或大按钮抢同一个焦点。
5. 固定记录跟随在审查批注后时，行距必须像连续纸页，而不是进入新的卡片区。

## 设计原则

- 主次先于装饰：原始记录保持 `16px` 全墨正文，Agent 是 `13px` 辅助批注，分类和动作再弱一级。
- 一条批注一条轴：角色、进度、问题、分类、回复和动作都贴近源记录文字轴；关闭按钮只作为右上工具，不改变阅读起点。
- 命中区不等于可见空白：按钮保持 `44px` 真实触控目标，但文字和边界不需要显示成一整块按钮带。
- 右轨只管导航：Search、Calendar、Settings、Export 和内容目录继续属于右侧装订系统，Agent 不移动、不遮挡、不复制这套导航。
- 可移除：所有改变只落在 CSS、文案和测试证据，不改变记录数据、分类写入、账号隔离、同步、离线或备份格式。

## 本轮落地方案

1. 将移动 Diary Agent 的元信息改为一行稳定 metadata：左侧 `Agent`，右侧进度。进度不再作为悬浮角标压在问题上方。
2. 让问题文本独占下一行，并为右上关闭按钮保留清晰空间；关闭按钮继续有 `44px` 命中区和约 `28px` 可见圆形面。
3. 分类结果保留为唯一 `Domain / Category` 标签，但颜色和底色降噪，使它更像“建议结果”而不是第二个主按钮。
4. 回复输入保持完整写入宽度；一到两个未解决动作继续紧贴输入下方右对齐，避免压缩中文占位或形成整行按钮墙。
5. 固定记录接在批注后只保留一个小组级间距，继续使用开放纸面和手绘行分隔，不引入卡片。

## 验证方式

- `npm run design:check`：验证设计规范结构和链接。
- `npm test -- tests/agent-review-model.test.mjs`：验证分类问题不重复路径、原始记录不被自动改写、计划/日记 Agent 契约不退化。
- `E2E_TEST_FILTER="diary Agent" npm run test:e2e` 或完整 `npm run check`：验证 320/390px 回复宽度、44px 目标、右轨不移动、截图证据和无横向溢出。

## 退出条件

如果真实手机查看仍然觉得 Agent 像第二段正文、关闭按钮不明显、分类结果不够清楚，或右侧装订轨和批注互相抢注意力，本轮样式应继续隔离在 LN-074 Rework 下，不进入 Accepted。回滚只需要撤销 Agent 批注样式和对应说明，不需要迁移任何用户数据。
