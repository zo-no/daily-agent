# Google 日历与今日记录复盘工作流介绍

## 结论

LN-081 在 `/insights` 增加了一个“日历与日记复盘”区块。它先在浏览器内比较当前账号当天缓存的 Google 日历事件与当天记录，直接给出匹配数、未记录日程、日程外记录和时间重叠；只有用户看过发送范围并再次确认后，才会把有明确上限的匿名投影交给 AI Agent（执行固定生成任务的模型）生成补充建议。整个能力只读、只在当前页面会话中存在，不修改记录、计划或日历。

同一份输入结构和输出校验也注册到了 Mastra Studio。开发者可以用合成数据观察工作流在调用 Agent 前暂停，并分别验证批准和拒绝路径。Studio 是本地调试面，不读取产品账号、缓存、Supabase 或 Google，也不替代产品验收。

## 用户流程

```text
当前账号当天缓存的 Google 日历事件 ─┐
                                      ├─ 浏览器本地比较 ── 展示事实与差异
当前账号当天记录 ─────────────────────┘                         │
                                                               ▼
                                                    查看字段、数量与排除项
                                                               │
                                             取消 ──────────────┴─ 明确批准
                                             零请求                   │
                                                                      ▼
                                               已认证同源接口 → Agent 一次调用
                                                                      │
                                                                      ▼
                                               严格校验 → 当前会话内建议
```

打开 `/insights` 不会触发 AI 请求。本地比较会先运行；没有当天日历缓存时，页面只显示空状态，不提供远程分析入口。用户打开 AI 操作后会看到实际事件数、记录数、发送字段和“不写入”的说明。取消产生零次请求；批准产生至多一次请求。停止、超时、离线、限流、无配置或无效返回只会显示可重试状态，不会伪造结果。

当账号、日期、日历事件或记录发生变化时，来源指纹（fingerprint，一次有界输入的确定性摘要）会变化，旧请求和旧结果随即失效。跨日数据、其他账号数据和完整文档不会进入这次复盘。

## 本地与远程边界

浏览器先把真实来源投影成一次请求内有效的匿名 ID，例如 `event-001` 和 `entry-001`。批准后，请求只包含以下内容：

- 请求元数据：schema 版本、随机 request ID、当天日期、来源 fingerprint、语言。
- 最多 40 项当天日历事件：匿名 ID、标题、开始/结束分钟数、是否全天。
- 最多 80 条当天记录：匿名 ID、时间、正文。

请求不会包含真实账号、日历、事件或记录 ID，也不会包含 Google access token、链接、地点、参与者、事件详情、标签、分类、附件、图片、计划、其他日期或完整文档。全天事件不会虚构时间。

Agent 输出只能包含一个概览和最多 12 条建议；建议类型限定为“日历中有但记录中没有”“记录中有但日历中没有”“日程时间重叠”，且只能引用本次请求已有的匿名 ID。伪造来源、未知类型、重复来源组合、越界文本或过期绑定会使整个结果失败，不会部分采用。

## Human-in-the-loop 放在哪里

Human-in-the-loop（人在回路）的人工确认位于隐私内容离开浏览器之前，而不是生成结果之后。产品页采用“披露 → 批准”的两步交互；Studio 工作流采用 Mastra 的 suspend/resume（暂停/恢复）机制，在 `approve-calendar-diary-review` 步骤暂停。拒绝后工作流直接以 `rejected` 结束，Agent 调用次数为零；批准后才进入 `generate-calendar-diary-review`，随后由 `normalize-calendar-diary-review` 复用项目校验器。

这个位置保护的是外部传输边界。人工确认不授予写权限，生成结果也不能成为命令；工作流未注册工具、记忆、持久化或产品数据访问。

## 在 Mastra Studio 中查看

在仓库根目录使用 Node 22 启动 Studio：

```bash
nvm use
npm run studio
```

打开 `http://localhost:4111/workflows/calendarDiaryReviewStudioWorkflow/graph`。选择运行工作流并输入下面的合成数据，禁止粘贴真实日历或私人记录：

```json
{
  "schemaVersion": "calendar-diary-review-v1",
  "requestId": "studio-demo-1",
  "targetDate": "2026-09-04",
  "sourceFingerprint": "fnv1a-1234abcd",
  "locale": "zh-CN",
  "events": [
    {
      "id": "event-001",
      "title": "项目评审",
      "startMinute": 600,
      "endMinute": 660,
      "allDay": false
    },
    {
      "id": "event-002",
      "title": "发布日",
      "startMinute": null,
      "endMinute": null,
      "allDay": true
    }
  ],
  "entries": [
    {
      "id": "entry-001",
      "time": "10:40",
      "content": "完成项目评审并记录三个决定"
    }
  ]
}
```

运行后应先看到 suspended 状态，且尚未调用 Agent。点击恢复时输入 `{"decision":"approve"}` 会继续生成并校验结果；重新运行后输入 `{"decision":"reject"}` 会得到 `rejected`，不会调用 Agent。若本机没有配置 `DEEPSEEK_API_KEY`，仍可验证暂停和拒绝路径，批准后的真实生成会报告未配置。

## 实现边界与验证

生产接口仍是 request-scoped Route Handler；Studio 注册仅用于本机合成数据调试。Studio 的暂停状态属于本地开发运行信息，不是 Log Note 的历史记录，也不会进入产品备份或同步。

自动验证覆盖本地匹配、全天与重叠事件、40/80 上限、匿名 ID、严格请求/返回结构、认证与同源边界、过期结果、取消与拒绝零调用、批准一次调用、来源不变、五档宽度、键盘焦点，以及 Studio 的暂停/批准/拒绝调用次数。仓库质量门禁与设计检查用于防止既有记录、同步、备份和页面行为回归。

仍需单独完成的验收证据包括：真实 Google OAuth 数据核对、非敏感 Provider 结果质量与三次延迟、产品负责人 390px 视觉检查、14 天实际使用、部署环境验证。缺少这些证据时，LN-081 只能标记为 Returned，不能标记为 Accepted。
