# LN-067｜Google 日历同步准入与架构

## 用户结果

用户在 Log Note 中安排的本地计划可以同步到 Google 主日历；Google 主日历已有事件可以回到 Log Note 的日计划中作为只读时间背景。记录正文、分类和图片不发送给 Google。

## 第一版边界

- 设置 → 账号提供“连接并同步”“立即同步”“断开并清除缓存”。
- 单独请求 `https://www.googleapis.com/auth/calendar.events`，不复用或扩大 Supabase 登录会话。
- access token 只保存在当前页面内存；不写入 Log Note JSON、Supabase、备份、Service Worker 或日志。
- 仅使用 `primary` 日历。
- Log Note 计划写入 Google 时携带 `extendedProperties.private.logNoteManaged=true` 与 `logNotePlanId`。
- Log Note 只更新或删除带上述私有标记的事件；Google 原有事件在 Log Note 中只读。
- Google 事件缓存使用账号隔离的独立本地 key，不进入 Log Note 主数据、云端文档或备份。
- 首次与手动同步读取今天前 30 天至后 90 天；全天与跨日事件按日期展示，不改写为伪时间块。
- 不做后台定时任务、系统提醒、循环日程编辑、多日历选择或 Agent 自动改日程。

## 同步规则

1. 先完整读取 Log Note 标记事件，再读取时间范围内的主日历事件。
2. 本地计划没有远端事件时创建；已有远端事件且标题/时间不同则更新。
3. 远端存在标记事件、但本地计划已不存在时删除该远端事件。
4. Google 原有事件替换对应时间范围的本地只读缓存；请求失败时保留旧缓存。
5. API 操作全部成功后才提交新的 event ID/etag 引用和缓存；部分失败返回明确结果，不把失败伪装成已同步。

## 失败与撤销

- 未配置 Client ID 时应用仍可构建、记录和离线使用，设置页只说明需要配置。
- 拒绝授权、token 过期、离线、限流或 Google 服务错误不改变本地计划。
- 断开连接只清除 access token 与本地 Google 事件缓存，不删除 Google 日历事件。
- 删除本地计划后，只有下一次成功同步才会删除对应的 Log Note 标记事件。

## 验收

- 纯函数测试覆盖普通、跨日、全天、取消事件与私有标记映射。
- 重复同步不重复创建事件；未标记的 Google 事件永不写入或删除。
- 320/390/1280 设置与日计划无横向溢出，关键目标不少于 44px。
- `npm run check` 全绿；真实验收使用测试日历完成创建、更新、删除、读取、断开和重新连接。

## 外部配置

Google Cloud 需启用 Calendar API，并在现有 OAuth Web Client 中加入本地 origin `http://127.0.0.1:3100`（如使用 localhost 也需单独加入），前端只配置公开 Client ID：

```text
NEXT_PUBLIC_GOOGLE_CALENDAR_CLIENT_ID=xxxx.apps.googleusercontent.com
```

Client Secret 不得进入浏览器、仓库或 `NEXT_PUBLIC_*`。
