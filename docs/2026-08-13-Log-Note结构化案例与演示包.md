## 一、结构化案例

### 1. 背景问题

个人记录工具很容易在两个方向失控：一是记录前要求选择太多结构，导致真正想记的时候放弃；二是不断加入 AI、同步、社交和自动化，功能变多，却让原始记录更难掌控、更难恢复。

Log Note 当前阶段选择先解决一个窄问题：作者在手机上能以很少的决策记录真实事件或观察，之后仍能浏览、搜索、纠正、删除、备份、恢复，并在首次在线加载后离线继续使用。

核心链路固定为：

```text
快速记录 → 浏览 → 搜索 → 编辑 / 删除 → 备份 / 恢复 → 离线使用
```

### 2. 目标与约束

目标不是增加功能数量，而是建立可重复演示、可自动回归、可进入真实使用验证的 MVP 基线。

关键约束：

- 普通快速记录打开编辑器最多 1 个动作，输入后最多 1 个保存动作。
- 模板和结构是可选能力，不得成为普通记录的必填步骤。
- 核心链路不依赖账号、API Key 或在线服务。
- 原始记录不得被 AI、迁移或派生功能静默改写。
- 完整 JSON 是支持恢复的备份；Markdown 是可读归档，不冒充完整恢复格式。
- 损坏、旧版或无效恢复输入不得覆盖当前有效数据。
- AI 原型继续隔离，未经产品、架构、隐私评审和明确授权不合入主线。

### 3. 关键决策

1. **先窄后宽**：首要用户明确为作者本人，先证明个人长期使用价值，再讨论更广人群。
2. **本地数据为权威来源**：当前使用浏览器 `localStorage`，不引入账号、数据库或云同步。
3. **快速记录优先**：首页的主要工作是快速记；高级结构放在次级路径。
4. **结构与原文分离**：领域、分类、模板帮助组织记录，但不反向静默改写原始内容。
5. **恢复优先于扩展**：在继续加功能前，先建立失败保留、备份提示、恢复前验证与确认替换。
6. **结果必须经过验收**：执行者返回不等于完成；总控独立核对验收标准和证据后才接受，并在同一轮拉取下一项。
7. **单写多读**：主工作区同时最多一个写任务；研究、日志分析和独立验证可以并行，重叠写范围必须串行。

### 6. 失败与恢复

#### 数据失败边界

曾识别出读取或迁移失败后默认数据可能回写相同 `localStorage` key 的覆盖风险。收口后的策略是：保留原 payload，禁止自动写入默认数据；只有用户确认恢复有效 JSON 后才恢复持久化。损坏恢复文件不会替换当前数据。

#### 执行失败边界

持续迭代调度研究的临时子 Agent 首次遇到 429。总控没有创建重复任务，而是在原 Agent 缩小范围后重试并接收结果。该过程验证了“限流、测试失败、宿主截断或意外结束属于原任务恢复，不是新建重复任务或停止项目的理由”。

#### PWA 升级恢复

自动化将 worker 从旧测试版本切换到当前测试版本，验证激活后只保留当前缓存；随后恢复仓库版本 `v4`，再次确认对应缓存状态。结果文件中 `failure` 为 `null`。

## 二、5–8 分钟演示脚本

建议总时长约 6 分 30 秒。使用专门的演示浏览器 profile 和脱敏数据；不要打开包含真实私人记录的日常 profile。

### 0:00–0:40｜问题与边界

讲述：

> Log Note 先解决一个很窄的问题：有东西想记时，不被分类和复杂功能打断；之后还能找回、纠正、备份恢复，并在断网时继续用。当前所有数据保存在本地浏览器，不需要账号、API Key 或在线服务。

屏幕：打开首页，指出首页只有一条主要记录路径；说明模板是可选项。

### 0:40–1:40｜快速记录

1. 点击 `+` 打开普通记录编辑器。
2. 输入一条预先准备的脱敏演示文本，例如“演示：周五前核对方案中的恢复边界”。
3. 不选择额外分类或字段，直接保存。
4. 刷新页面，确认记录仍在。

讲述重点：普通记录不增加必填分类、模板或网络依赖；这是一条演示记录，不计入 14 天真实验证。

### 1:40–2:40｜搜索与编辑

1. 打开搜索，输入演示文本中的唯一关键词“恢复边界”。
2. 从结果进入该记录。
3. 将文本改为“演示：周五前完成恢复边界复核”。
4. 保存并再次搜索，确认新文本可找到。

讲述重点：记录不是一次性写入；用户可以找回并纠正原文。若展示删除，使用另一条临时演示记录，避免误删后续环节需要的数据。

### 2:40–4:10｜备份、安全恢复与可读导出

1. 打开设置，指出浏览器 profile、设备、域名和端口变化可能使本地数据不可见。
2. 导出完整 JSON，说明它包含记录和领域 / 分类 / 模板等完整状态，是支持恢复的格式。
3. 导出 Markdown，快速打开确认正文可读；说明 Markdown 用于阅读归档，不替代完整恢复。
4. 选择刚导出的演示 JSON，展示恢复前验证摘要和确认步骤。
5. 用户确认后执行恢复，刷新并搜索“恢复边界”，核对记录和结构仍在。

讲述重点：恢复是“先验证、再确认、再替换”；无效或损坏输入不得覆盖当前数据。正式演示前应另存一份恢复前 JSON 安全副本。

### 4:10–5:30｜离线使用证据

1. 展示 [PWA 验证结果](../output/playwright/pwa/results.json) 中离线路由 `/`、`/templates` 和持久化测试记录字段。
2. 展示 [离线记录截图](../output/playwright/pwa/pwa-verified.png)。
3. 如现场环境可控：首次在线打开后切换浏览器离线模式，打开首页，新增一条明确标注“离线演示”的记录并刷新。
4. 如现场离线切换不稳定：只展示已保存证据，不临时反复重试或改数据。

讲述重点：自动化证明的是受控 Chromium 环境中的离线能力，不推广为所有设备均已验证。

### 5:30–6:10｜安装与升级证据

展示 [PWA 验证结果](../output/playwright/pwa/results.json)：

- manifest 为 `standalone`；
- 192 / 512 PNG 图标均返回 200，purpose 包含 `maskable`；
- Chromium installability errors 为空；
- worker 从旧版本升级到当前版本后，旧缓存被清理；测试结束恢复 `v4`。

讲述重点：升级证据来自自动化版本与缓存状态，不把“可安装条件通过”说成已在所有平台完成真人安装体验。

### 6:10–6:40｜真实结论与下一步

讲述：

> 今天能确认的是：核心链路已经具备可靠演示和自动回归基线。还不能确认的是：它是否能连续 14 天自然地服务真实记录，是否能在真实情境中帮助找回有用信息，以及是否影响了其他人的理解或决策。下一步是按协议完成真实使用，再安排两次真实展示并原样记录反馈。
