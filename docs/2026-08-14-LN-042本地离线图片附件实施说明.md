# LN-042 本地离线图片附件实施说明

## 用户可见结果

- 普通自由文本记录可在“更多”中添加一张 JPEG、PNG 或 WebP 图片，不增加快速记录的默认步骤和常驻工具栏高度。
- 保存后，图片在时间视图与分类视图中跟随所属记录展示；搜索结果显示图片数量。
- 图片只从 IndexedDB Blob 创建的 `blob:` URL 展示。Markdown 中的远程图片语法继续作为文字，不会触发网络请求。
- 图片缺失、损坏或被浏览器清理时显示安全占位；记录正文、搜索、编辑、JSON 和 Markdown 不受影响。

## 存储与容量

- `localStorage` 只保存版本 3 的记录状态和附件引用：稳定 ID、类型、字节数、文件名、替代文字与创建时间。
- 图片二进制位于 IndexedDB `log-note-attachments/images`，不使用 data URL、base64、OPFS、数据库或上传服务。
- 首切片限制为每条普通记录一张图片，单张 5 MiB，总存储 50 MiB；支持 JPEG、PNG、WebP，不接受 SVG。
- 设置页显示本地图片数量与占用，并提供显式孤儿清理。删除记录或放弃新草稿时会尽力回收对应 Blob。

## 便携备份

- `.lnbackup` 使用无依赖二进制容器：固定签名、UTF-8 JSON 清单、随后顺序拼接原始图片字节。
- 清单包含版本化状态、附件元数据与每个文件的 SHA-256；恢复前校验签名、版本、UTF-8/JSON、引用一致性、长度、类型和哈希。
- 恢复时为图片分配新的本地 ID，避免覆盖当前浏览器中的同名 Blob。校验或保存失败时不替换当前文字状态，并回收本轮已写入的文件。
- 现有 JSON 备份继续恢复文字和结构，但不携带图片二进制；缺失图片以占位显示。带图片迁移必须使用便携备份。

## 失败回退与边界

- 图片写入失败不会改写草稿，用户仍可保存文字记录。
- 损坏、截断、超限或图片不完整的便携包会被拒绝，当前记录不被替换。
- 当“当前图片 + 待恢复图片”会临时超过 50 MiB 时，恢复会 fail-closed，不会先删除当前图片来腾出空间。
- 本切片不包含多图、图片编辑/压缩、相机专用入口、拖拽排序、远程链接、服务器、账号、数据库或自动上传。

- 移动浏览器场景覆盖添加、保存、刷新、分类展示、JSON 不含二进制、便携导出、清空后恢复、损坏包不覆盖、缺图占位和 320/390/1280 无横向溢出。
- PWA 场景在网络完全关闭后添加图片、保存、刷新，并确认 IndexedDB 图片仍通过 `blob:` URL 展示。
