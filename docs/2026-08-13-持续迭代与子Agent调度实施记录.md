# Log Note 持续迭代与子 Agent 调度实施记录

- 日期：2026-08-13
- 项目：P01｜O1·KR4 Log Note MVP
- 总控任务：P01-T00
- 目的：解决“执行任务完成后项目经常空转”，同时防止以持续迭代为名不断堆功能、破坏快速记录主线。

## 1. 我发现了什么问题

项目原有机制能发现限流、`systemError`、异常结束、测试失败和会话停摆，也能在原任务续跑。但它主要是一个 watchdog（异常巡检器），不是 scheduler（持续调度器）。

直接问题是：

```text
执行任务返回
→ 看板进行中变空
→ 没有 systemError
→ 心跳认为“正常”并静默
→ Ready 队列还有任务，但项目不再推进
```

原看板还缺少可机器判断的 Ready 定义，无法稳定区分“可以立即做”“依赖未满足”“等待用户产品决策”和“缺少权限/任务号”。执行者的 `returned` 与总控的 `accepted` 也没有形成一个原子交接，因此“代码写完”容易被误认为“任务完成”。

## 3. 最终采用的控制循环

每次总控启动、心跳唤醒或执行者返回时，执行同一个 reconcile：

```text
读取看板、任务状态、工作区和验证证据
                ↓
Ready → 已分派 → 进行中 → 已返回 → 独立验证 → 已验收 → 拉取下一项
                         ↘ 合法等待 / 原任务返工 ↗
```

具体规则：

1. 原任务未通过验收时，继续原任务，不创建重复任务。
2. 执行者只能返回证据，不能替总控完成业务验收。
3. 总控核对验收标准、diff、测试、构建、截图或文档后才能接受。
4. 接受后先更新事实源，再在同一轮拉取 Ready 队列第一项。
5. Ready 非空、无合法等待且主工作区写槽空闲时，项目不得空转。
6. 主工作区同时只有一个写任务；只读研究、代码探索、日志分析和独立验证可以并行。
7. 限流、测试失败、宿主截断、意外结束和子 Agent 返回都不是停止条件，而是原任务恢复条件。

只允许停在以下状态：

- 等待用户选择、审批、登录或 API Key；
- 等待真实外部反馈、观察期或系统状态变化；
- 存在权限、事实源或并发写冲突；
- 没有满足依赖的 Ready 工作；
- 项目目标及验收证据全部完成。

## 6. 如何防止项目越来越难用

任何新功能先回答：

1. 它改善快速记录、浏览、搜索、编辑/删除、备份恢复或离线中的哪一个行为？

## 10. 固定记录体验是怎样分任务完成的

用户连续指出了固定记录不在首屏、不能直接输入、移动端体验差，以及模板/设置界面不统一。总控没有把这些问题塞进一个大任务，而是保留单写槽并拆成三个稳定执行范围：

| 任务 | 负责范围 | 最终结果 |
| --- | --- | --- |
| P01-T05 / LN-027 | 首屏布局、信息层级、响应式可见性和触控尺寸 | 桌面时间线与固定记录同屏双栏；移动端固定记录优先；输入为 16px，保存触控区 45×45px |
| P01-T06 / LN-028 | value、structured、legacy free 填写模型，旧数据兼容和保存语义 | 首页原地填写；旧正文不被迁移或改写；持久化失败保留草稿并明确提示 |
| P01-T07 / LN-029 | 只读跨端验收、失败路由和最终门禁 | 在真实 `localhost:3100` 验证 320/390/1280、键盘/触控、离线、旧备份、无障碍与视觉回归 |

执行顺序是 `T05 → T06 → T07`。T07 首次验收发现两个问题后，没有自行修改实现：运行版本漂移退回 T06，移动端 13px 字号和 30×30px 保存按钮退回 T05。每次修复均在原稳定任务续跑，未创建重复任务。

### 10.1 运行版本漂移怎样定位

用户在真实 `localhost:3100` 看到的仍是旧“去记录”按钮，而主工作区源码和测试都已经渲染输入框。总控与执行任务对比实际 DOM、端口监听和 `.next` 构建后确认：长驻 `npm start` 进程一直加载早期构建，源码正确不代表用户正在使用的新版本。

处理方式是只停止明确的旧进程，以最新 production build 在同一 3100 端口重启，再直接对这个地址验收。真实页面随后出现 5 个单值输入框；保存晨重后进度从 0/6 变为 1/6，刷新仍保留。项目因此新增了一条实际经验：浏览器缺陷复现必须同时核对源码、构建产物、监听进程和真实运行 DOM，不能只看自动化或任务状态。

### 10.2 最终验收证据

- 自动门禁：34/34 单测、6/6 移动端 E2E、PWA、生产构建、设计校验和 `git diff --check` 通过。
