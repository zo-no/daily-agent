# 模板与设置管理页面统一实施说明

## 用户问题

首页中的“记录结构”和“设置”都属于一级管理入口，但此前进入方式不同：记录结构打开独立页面，设置打开长弹窗。它们在 URL、返回方式、页头、内容宽度、移动端滚动和视觉层级上不一致。

## 本轮做法

1. 把设置从首页弹窗迁移为独立 `/settings` 页面，使其可刷新、可复制链接并支持浏览器前进后退。
2. 新增共用的 `ManagementHeader` 与管理页骨架，让 `/templates` 和 `/settings` 使用相同的：
   - 左侧返回记录页按钮；
   - `Log Note` 品牌眉题；
   - 页面标题字号和 76px／移动端 66px 页头；
   - 940px 页面外壳和 760px 主工作区；
   - 16px 移动端边距与自然文档滚动。
3. 首页齿轮由控制弹窗的按钮改为 `/settings` 链接，并移除首页中的设置状态和数据管理函数，避免首页承担管理页职责。
4. 设置页直接铺开展示导出、恢复、Markdown 格式、备份保护和安装说明；不使用遮罩、模态框或嵌套高度滚动区。
5. 模板的字段等对象级深度编辑继续使用侧边抽屉；恢复替换仍保留浏览器确认，维持防误操作边界。
6. 将 `/settings` 加入 PWA 应用壳，并扩展移动端与离线 E2E。

## 关键文件

- `src/app/management-header.js`、`src/app/management-header.css`：共用管理页骨架。
- `src/app/settings/page.js`、`src/app/settings/settings-page.js`：独立设置路由与数据操作。
- `src/app/home-header.js`、`src/app/page.js`：首页设置入口改为链接并去除弹窗状态。
- `src/app/templates/template-screen.js`：模板页改用共用页头。
- `public/sw.js`：离线应用壳加入 `/settings`。
- `e2e/run-mobile.mjs`、`e2e/run-pwa.mjs`：验证独立设置页、恢复、返回和离线访问。

## 防退化边界

- 没有重做模板列表、记录输入或字段编辑器。
- 没有取消记录编辑、模板对象编辑等确实需要专注上下文的抽屉。
- 没有改变备份文件格式、恢复校验、Markdown 配置数据或本地优先策略。
- 没有新增账号、联网依赖、必填步骤或默认弹窗。

## 后续观察

模板页仍保留自己的“导出”抽屉，而设置页也包含结构导出。当前优先保证入口层级和 UI 一致；若真实使用表明导出入口重复造成困惑，可在后续独立任务中把模板页导出按钮定向到 `/settings#export`，不与本轮混做。
