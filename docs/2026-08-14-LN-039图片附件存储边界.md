# LN-039 图片附件存储边界

## 当前决定

本轮不实现图片 UI、上传、粘贴转换、远程图片渲染或数据结构变更。基础 Markdown 展示器刻意不解析 `![alt](url)`：它按原文字面显示，不创建 `<img>`，因此不会默认访问网络。

禁止把图片文件转为 data URL 或 base64 写入 `entry.content`、`localStorage` 或完整备份。这样做会快速触达浏览器配额、放大每次状态写入和 JSON 备份，并可能导致正文与图片同时无法保存。

## 待选择的实现模式

后续实现前必须由用户在以下模式中选择其一：

1. **本地上传并离线保存**：文件保存在独立的本地二进制存储（优先 IndexedDB/OPFS），正文只保存稳定引用；备份、恢复、删除、孤儿清理、容量提示和跨浏览器兼容必须一起设计。
2. **网络图片链接**：正文保存显式 URL，但展示前必须由用户确认允许联网；需要处理隐私泄露、跟踪像素、失效链接、混合内容、超大资源和离线不可用。

两种模式不得在同一引用上静默切换，也不得在没有明确选择时自动上传、下载或迁移图片。

## 隔离接口

图片能力若获批准，应通过独立适配器接入，不让记录数据层直接持有 `File`、`Blob` 或 data URL：

```text
AttachmentStorage
  put(file, metadata) -> AttachmentRef
  get(ref) -> Blob | unavailable
  remove(ref) -> removed | retained
  inspect(ref) -> metadata + availability
  export(refs) -> portable attachment bundle
  restore(bundle) -> validated refs, without replacing current data on failure
```

`AttachmentRef` 至少需要稳定 ID、存储模式、媒体类型、字节数和可选替代文字。远程模式还需要原始 URL；本地模式不得把二进制内容内联到引用。

## 上线前风险门禁

- 图片失败、旧引用或损坏备份不得覆盖正文或当前附件集合。
- 删除记录时附件回收必须可恢复或延迟执行，避免共享引用误删。
- 完整 JSON 备份仍需可读；二进制附件必须使用独立可验证的便携包。
- 本地模式需验证配额、原子写入、离线读取和浏览器清理风险。
- 网络模式需默认不加载，明确显示将访问的域名，并支持永久关闭。
- 320px 编辑器不得因附件入口增加 quick record 步骤或工具栏高度。
