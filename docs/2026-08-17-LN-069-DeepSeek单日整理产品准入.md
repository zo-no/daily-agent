# LN-069 DeepSeek 单日整理产品准入

## 1. 改善的核心行为

改善 `browse → organize` 中的语义分类准确率。快速记录路径、首页主任务和保存步数不变。

## 2. 用户证据

用户已完成单日整理流程的多轮交互复核，并明确要求“把 AI 能力做通”并提供 DeepSeek API 凭据。2026-08-18 用户进一步纠正：整理应按已有“领域 → 分类”归档，而不是给记录添加标签。

## 3. 默认界面成本

不新增首页控件、弹窗、聊天页或必填字段。继续使用现有“整理 N 条记录”动作；仅在远端模型不可用时通过 Toast 告知已改用本地规则。

## 4. 离线、隐私、可逆与备份

- 只有用户主动点击整理才发起网络请求。
- 只发送所选日普通记录的 `id/content/currentCategoryId`、有界的已有分类路径与提示、最多 24 条按分类均衡抽取的历史示例；不发送账号邮箱、附件、标签或完整云端文档。
- API Key 只位于服务端环境变量，不进入浏览器 bundle、Supabase、备份或日志。
- DeepSeek 返回仅生成会话内“领域 / 分类”建议；每条记录最多一个已有 `categoryId`。只有用户显式应用才移动分类，正文、标签、模板、附件、日期和时间不变，现有撤销仍可用。
- 离线、超时、限流、缺配置或输出无效时使用现有本地规则，不阻塞其他功能。

## 5. 验证与隔离

- 单测：请求体上限、记录/示例裁剪、只允许已有 category ID 和当次 entry ID、每条最多一个非当前分类、损坏 JSON、模型超时、限流和认证失败。
- 浏览器：远端成功、远端失败降级、应用/撤销及原文不变。
- 可移除性：远端 provider 保持与本地 provider 相同的 `analyze` 合约，删除 API route 和远端 adapter 后即可回到本地规则。

## 6. 失败或不采用条件

如果手工真实记录验证中建议接受率低于 50%、无效输出超过 20%、常见请求超过 8 秒，或隐私/成本无法接受，远端 AI 将保持隔离或移除，智能整理继续使用本地规则。
