# LN-033 固定记录分类归属实施说明

## 用户问题

固定记录不应脱离普通记录形成第二套分类体系。固定记录属于哪个分类，就应在该分类中浏览，并在 Markdown 中跟随同一领域与分类导出。例如一条归属“学习 / 学习记录”的固定记录，应与学习记录共置，而不是被集中到单独的固定记录组。

## 方案

- 分类视图统一采用“领域 → 分类 → 该分类中的普通记录与固定记录”。
- 已填写固定记录以记录自身的 `categoryId` 为归属真源。
- 未填写固定模板尚无记录实体，因此以模板的 `categoryId` 决定出现位置。
- 编辑已有固定记录时保留原 `categoryId`；只有新建时采用模板分类，避免一次编辑造成静默搬家。
- 时间视图继续保留页面底部的快速固定记录区，维持低摩擦填写；它不改变记录归属或导出语义。
- Markdown 今日导出与全部导出继续读取记录自身 `categoryId`，与分类视图一致。

## 具体实现

- `src/app/page.js`：分类视图将普通记录和固定项按领域、分类共置；已填写固定项按 `entry.categoryId` 分组，空模板按 `template.categoryId` 分组；内联更新保留已有记录分类。
- `src/app/fixed-records.js`：增加嵌入分类的展示模式，复用原有 value、structured、legacy free 保存与清空逻辑。
- `src/app/home-timeline.css`：增加领域、分类和内嵌固定项的层级样式。
- `src/app/templates/templates.css`、`src/app/templates/template-screen.js`、`src/app/entry-composer.css`：关键移动端菜单、选择器、关闭、完成和模式切换触控目标提升至至少 44px；模板编辑关闭按钮补充可访问名称，移动端编辑页头保持可达。
- `tests/data.test.mjs`、`e2e/run-mobile.mjs`：增加“模板属于健康、已有固定记录属于学习”的反例，验证分类页、保存和两种 Markdown 的归属一致。

## 数据与兼容边界

- 未修改 schema、版本号、历史正文、JSON 备份恢复契约或 Markdown 格式设置。
- 不迁移旧数据，不因查看或编辑静默改变已有记录分类。
- 已知 P2 风险：同一天同一周期模板若存在多条记录，当前页面仍选择第一条作为固定项展示，而 Markdown 会导出全部。此次不改变该兼容策略，后续应独立决定是拒绝重复、合并还是展示额外历史项。

## 调度方式

本轮由项目总控拆为三类工作并串行收口：T08 主实现与返工、T10 Markdown 契约只读核验、T09 跨端独立验收；同时使用只读子 Agent 审查归属反例与移动端交互。执行任务的返回只作为证据，最终由项目总控精确移植、补专项 E2E 并独立重跑门禁。
