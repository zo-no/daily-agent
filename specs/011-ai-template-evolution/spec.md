## Clarifications

### Session 2026-09-01

- “首次使用”按当前账号首次主动进入模板助手的创建场景判断，不按每次登录、每台设备或每次打开应用重复触发；普通快速记录不出现强制 AI 引导。
- 账号没有填写模板需求时，继续使用产品内置的本地默认结构，外部 AI 请求数必须为 `0`；不为“看起来像 AI”而远程重写一份默认模板。
- 账号明确填写需求时，一次只生成一个可直接预览和保存的完整模板，不一次生成整套领域树，也不替换现有默认结构。
- 已有模板的“记忆”在首期仅指所选模板当前内容，以及本机可从该模板历史使用中派生的非正文统计；默认不发送历史原文，不建立向量库或可自写的长期 Agent 记忆。
- 已有模板优化默认是保守补丁：不改变所属分类、记录类型、输入模式、周期配置，不删除、重排或更换既有字段 ID，最多新增一个字段。
- Agent 只有在用户主动要求整理、现有领域/分类无法合理承载所选记录时，才可以提出一个新的“领域 + 分类 + 模板”结构包；它不能直接创建结构、移动记录或改写原文。
- 所有 AI 结果都是临时提案。通过本地结构校验、差异预览与用户显式确认后，现有本地优先写入链路才可以落盘；拒绝、离线、失败或过期提案不产生任何数据变化。

## User Scenarios & Testing *(mandatory)*

Automated regression is mandatory for every implemented story. Real-environment or manual evidence
MUST be added when automation cannot prove the acceptance claim.

### User Story 1 - 首次创建一个可用模板 (Priority: P1)

作者从结构管理页主动进入模板助手。没有填写需求时，系统直接采用内置默认结构且不调用模型；填写了具体需求时，系统一次给出一个完整模板提案，作者可以在保存前检查每个字段。

**Why this priority**: 这是最窄的 0→1 价值：减少从空白模板开始理解字段、输入模式和提示语的成本，同时保持普通记录路径不变。

**Independent Test**: 分别用空输入和明确输入进入创建场景；拦截网络并验证空输入为零请求，明确输入恰好产生一个受限请求和一个完整、可校验、尚未保存的模板提案。

**Acceptance Scenarios**:

1. **Given** 当前账号主动打开首次创建场景且没有填写需求，**When** 选择继续，**Then** 系统使用内置默认结构、发送零 AI 请求、产生零重复模板，并可立即返回记录主链路。
2. **Given** 当前账号填写“我想记录每次跑步的距离、时长和感受”等明确需求，**When** 请求生成，**Then** 系统只返回一个包含名称、记录方式、提示语及必要字段的完整模板提案，且保存前不改变账号数据。
3. **Given** 请求离线、超时、未配置或返回非法结构，**When** 生成失败，**Then** 默认结构和手动新建入口仍可用，页面不伪造本地 AI 结果，也不新增空模板。

---

### User Story 2 - 保守优化已有模板 (Priority: P1)

作者在一个已有模板的编辑面板中请求优化。系统结合模板当前状态和不含正文的使用统计，只建议少量、可解释的变化，并清楚展示“保留什么、修改什么、为什么”。

**Why this priority**: 已有用户最需要的是降低微调成本，而不是让模型重建长期使用的结构；保护字段身份和历史兼容比生成更多内容更重要。

**Independent Test**: 选择一个有历史使用记录的模板并请求优化，返回同时包含允许项和禁止项的合成响应；验证最终只保留允许的小补丁，原模板与记录在确认前字节不变。

**Acceptance Scenarios**:

1. **Given** 一个已有模板及本机使用统计，**When** 作者请求“让它更容易填写”，**Then** 提案只能修改允许的文字或必填状态、最多新增一个字段，并解释每项变化与可用统计之间的关系。
2. **Given** 模型尝试移动模板、改变记录类型/输入模式/周期，或删除、重排、重置既有字段，**When** 响应进入校验，**Then** 整份提案被拒绝，现有模板保持不变。
3. **Given** 作者查看差异后拒绝提案，**When** 关闭优化面板，**Then** 不保存 AI 输出、不产生同步、不修改历史记录或模板。

---

### User Story 3 - Agent 提出一个新分类结构包 (Priority: P2)

作者主动让 Diary Agent 整理所选记录。Agent 必须先匹配现有结构；只有现有领域和分类确实无法表达这些记录时，才提出一个包含新领域、新分类和首个模板的完整结构包。

**Why this priority**: 新领域能力补足长期使用中出现的新生活主题，但它扩大了现有“只选已有分类”的安全边界，因此必须晚于模板创建和保守优化验证。

**Independent Test**: 使用一组可被现有分类覆盖的记录和一组无法覆盖的记录；前者只能返回已有分类建议，后者至多返回一个带来源 ID 和理由的结构包，二者都不能直接写数据。

**Acceptance Scenarios**:

1. **Given** 所选记录可以被一个已有分类合理承载，**When** Agent 整理，**Then** 它继续使用已有分类提案，不得为了展示能力而创建同义领域或模板。
2. **Given** 所选记录形成一个现有结构无法承载的明确主题，**When** Agent 整理，**Then** 它可以提出至多一个“领域草案 + 分类草案 + 完整模板草案”，并列出用于判断的现有记录 ID 与简短理由。
3. **Given** 作者确认新结构包，**When** 提案仍与当前结构版本一致，**Then** 三层结构在一次本地事务中创建；原记录保持原分类和原文，作者另行选择是否调整记录归属。

---

### User Story 4 - 安全预览、确认与降级 (Priority: P1)

无论从哪个入口生成，作者都先看到结构化预览和差异，再决定确认、编辑或拒绝。提案过期、账号切换、网络失败或平台不可用不能影响本地记录和现有模板。

**Why this priority**: 统一的提案边界让成熟工作流平台只负责生成，不获得产品写权限，是三种模式可安全共用的基础。

**Independent Test**: 对三种模式执行确认、拒绝、账号切换、结构并发修改、迟到响应和离线场景；仅“当前账号 + 当前结构指纹 + 明确确认”的有效提案可以进入既有本地写入链路。

**Acceptance Scenarios**:

1. **Given** 一个通过校验的提案，**When** 作者查看预览但未确认，**Then** 本地缓存、云端文档、备份内容和原始记录均不变化。
2. **Given** 提案生成后模板或结构已在另一操作中改变，**When** 作者尝试确认，**Then** 系统提示提案已过期并要求重新生成，不覆盖较新的状态。
3. **Given** 账号切换、页面离开、停止请求或迟到响应，**When** 旧请求结束，**Then** 旧提案被丢弃，不能出现在新账号或新上下文中。

### Edge Cases

- 首次打开助手时账号已有内置默认结构、已删除部分默认项、已手动新建模板，或另一设备已经完成过模板调整。
- 用户输入只含空格、超长文本、提示注入、凭证、URL、HTML，或要求一次生成多套模板。
- 模板名称与现有模板重名，领域/分类语义近似但文字不同，或者模型返回重复字段 ID、重复选项、未知字段类型。
- 已有模板从未被使用、使用次数很少、历史记录缺失 `templateId`，或使用统计因旧数据迁移不完整。
- 优化提案包含允许修改与禁止修改的混合内容；整份提案必须失败，不能静默应用其中一部分。
- Agent 的证据记录被删除、切换账号、改变分类或在响应返回前发生结构 revision 更新。
- Dify/模型服务离线、无配置、限流、认证失败、响应超时、非 JSON、超限或结构校验失败。
- 320/390/426/768/1280px、中文/英文长名称、键盘、屏幕阅读器、触控、reduced motion 和页面横向溢出。
- JSON 备份来自旧版本、包含 AI 创建的普通结构对象，或恢复后不再具备任何平台配置；结构仍须正常可编辑。

## Product Admission *(mandatory)*

### Core-Loop Contribution

改善“browse”与后续“search”前的结构质量，并降低作者维护模板的成本。它不改变普通快速记录的打开和保存动作，也不要求作者在记录前选择 AI、领域或字段。

### User Evidence

产品负责人明确提出三类需求：首次使用完成一个 0→1 模板、已有模板只做基于过去使用情况的小改、Agent 整理时能在必要时提出新领域和新模板；同时明确要求优先采用成熟平台或 Agent 工作流，不自行搭建通用编排框架。现有产品只有手动模板预设，现有智能整理和 Diary Agent 又被限定为已有分类，因此能力缺口可以从当前代码与产品边界直接核对。

### Default Interface and Recording Cost

结构管理页增加一个次级模板助手入口，已有模板的优化入口只出现在当前模板编辑面板；新结构提案只出现在用户已主动唤醒的 Diary Agent 会话中。首页不增加常驻按钮、首次登录不弹强制模态、不新增记录必填项。普通快速记录仍为一次打开、输入后一次保存。

### Offline, Account, Privacy, Reversibility, and Backup

空输入和内置默认结构完全本地完成。远程创建只发送用户需求、语言和去标识化的现有结构名称摘要；远程优化只发送所选模板及本机派生的 `useCount`、`activeDays`、`lastUsedAt`，默认不发送记录正文；Agent 新结构提案只发送用户当前主动选择且已经在既有 Agent 披露范围内的有限记录、现有结构摘要与语言。账号 ID、邮箱、访问令牌、附件、图片、计划、完整文档、其他账号数据和未选记录不得进入模型输入。访问令牌只用于同源服务端鉴权，不进入工作流或模型变量。

提案在会话内临时存在，确认后只创建或修改现有 `domain/category/template` 结构对象，继续经账号隔离、本地先写和 revision 检查同步。AI 不改原始记录、不自动调整 `entry.categoryId`。这些对象继续使用现有 JSON/Markdown/便携备份契约；移除 AI 入口不需要迁移或删除已确认的普通结构。

### Verification and Removability

纯函数测试覆盖输入白名单、结构指纹、使用统计、补丁限制、重复检测、结构包校验和应用事务；路由/适配器测试覆盖鉴权、同源、限流、超时、取消、大小和平台非法响应；浏览器测试覆盖零请求默认路径、一次请求、差异预览、拒绝、过期、账号切换、响应式与无障碍。真实平台只用合成数据完成首轮 PoC，真实笔记启用需独立隐私与部署验收。平台适配器、工作流 ID 和 UI 入口均须可关闭；关闭后手动模板管理、默认结构和既有 Agent 继续工作。

### Exit Condition

若 14 天内没有二次使用，确认率低于 50%，非法或不可应用提案超过 20%，正常请求频繁超过 8 秒，Token/平台费用变得不可接受，用户不信任外发边界，或任何账号、离线、原文、备份与质量门禁回归，则维持隔离或移除远程能力。新领域提案若大多数被现有分类替代，Phase 3 不进入主线。

### Admission Decision

- **Score**: `14/20` using the rubric in `product.md`
- **Decision**: `isolated experiment`
- **Red-line check**: 不允许静默改写原文、后台生成、跨账号复用、给平台写权限、增加普通记录步骤、破坏离线缓存或改变旧备份恢复语义；真实记录外发在完成 `LN-007/LN-009` 和独立数据边界验收前保持关闭。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 只在作者主动进入结构管理助手或主动唤醒 Diary Agent 后开始任何生成流程，MUST NOT 在登录、首页加载、记录保存或后台同步时自动调用。
- **FR-002**: 创建场景没有非空用户需求时，系统 MUST 使用内置默认结构并产生零外部 AI 请求、零重复模板和零额外 Token 消耗。
- **FR-003**: 创建场景存在明确用户需求时，一次确认 MUST 最多发起一个生成请求，并只返回一个未保存的完整模板提案。
- **FR-004**: 完整模板提案 MUST 包含名称、所属建议、`linear|periodic`、`free|structured|value`、提示语、标签、周期和字段的自洽组合；字段最多 6 个、标签最多 3 个、单字段选项最多 6 个，未知类型或超限 MUST 使整份提案失效。
- **FR-005**: 已有模板优化输入 MUST 仅包含所选模板当前状态、语言、作者本次要求及本机派生的非正文使用统计；默认 MUST NOT 包含历史记录原文、附件、图片、计划或其他模板的完整数据。
- **FR-006**: 已有模板补丁 MAY 修改名称、提示语、标签、字段标签/占位语/必填状态，并 MAY 新增至多一个新字段；MUST NOT 修改 `categoryId`、`recordType`、`inputMode`、`schedule`，也 MUST NOT 删除、重排、更换 ID 或改变既有字段类型/选项语义。
- **FR-007**: 优化理由 MUST 引用实际提供的模板状态或 `useCount/activeDays/lastUsedAt` 等统计；证据不足时 MUST 返回“无需调整”而不是编造历史偏好。
- **FR-008**: Diary Agent MUST 优先复用现有领域和分类；只有用户主动整理且现有结构无法合理承载所选记录时，才 MAY 返回至多一个新结构提案。
- **FR-009**: 新结构提案 MUST 同时包含一个领域草案、其下一个分类草案和该分类下一个完整模板草案，以及简短缺口理由和有效的 `evidenceEntryIds`；缺少任一层或证据 ID 未知 MUST 使整份提案失效。
- **FR-010**: 模型或外部平台 MUST NOT 生成最终持久化 ID、顺序或 revision；这些值只能在用户确认后的本地应用阶段由产品代码生成。
- **FR-011**: 三种模式 MUST 统一产出受版本控制的结构化提案，并在浏览器或同源服务端完成字段白名单、长度、枚举、重复名称、父子关系和业务不变量校验。
- **FR-012**: 每个提案 MUST 绑定账号上下文、入口模式和生成时的结构指纹；确认时任何上下文或指纹不一致 MUST 拒绝应用并要求重新生成。
- **FR-013**: 系统 MUST 在保存前展示新增/修改/不变项、理由、数据外发摘要和明确的确认/拒绝动作；打开预览、编辑预览或拒绝 MUST 不写数据。
- **FR-014**: 只有显式确认的当前提案可以调用既有本地优先提交能力；新结构包 MUST 在一次原子状态更新中创建父子关系，模板补丁 MUST 只更新目标模板。
- **FR-015**: 外部工作流平台和模型 MUST 只有“接收受限输入、返回提案”的权限，MUST NOT 获得 Supabase 服务角色密钥、本地存储访问、结构写工具、记录写工具或回调写权限。
- **FR-016**: 同源 API MUST 对每种模式使用独立输入白名单：create 只含不超过 2000 字符的用户要求、语言和结构名称摘要；refine 只含一个目标模板、用户要求和非正文使用统计；structure 只含现有结构摘要及用户主动选择的最多 12 条普通记录、每条最多 1000 字符。API 还 MUST 执行 Bearer 用户鉴权、账号级限流、`private/no-store`、HTTPS 上游、请求/响应各 64 KiB 上限和 20 秒服务端超时；访问令牌只用于验证，MUST NOT 转发给工作流或模型。
- **FR-017**: 停止、页面离开、账号切换、模式切换或后续请求 MUST 取消并废弃旧请求；迟到响应 MUST NOT 渲染或应用。
- **FR-018**: 工作流 MUST 在调用模型前执行空输入、本地默认、重复结构和基础规则分支；稳定说明与 schema MUST 置于可缓存前缀，动态账号内容 MUST 受限并置后。一次用户动作不得形成无上限 Agent 循环。
- **FR-019**: 离线、平台未配置、鉴权/限流/超时/上游失败、非法响应或安全校验失败 MUST 显示短暂不可用状态，并保留默认结构、手动模板编辑和现有本地 Agent 能力。
- **FR-020**: 所有入口、预览、确认、拒绝、停止与错误状态 MUST 支持键盘、明确焦点和至少 44×44px 触控；在 320/390/426/768/1280px 中英文内容不得造成页面横向溢出，非必要动效 MUST 尊重 reduced motion。

### Invariants and Non-Regression Requirements

- **NR-001**: Raw note content MUST remain unchanged unless the user explicitly edits it.
- **NR-002**: Previously authenticated offline use and account isolation MUST not regress.
- **NR-003**: Supported backup, restore, export, and old-data behavior MUST remain compatible.
- **NR-004**: The existing quality gate MUST remain green.
- **NR-005**: 普通快速记录继续不要求模板生成、AI 判断、分类确认或新增字段。
- **NR-006**: 现有 LN-071“仅建议已有分类并显式确认”的路径保持可用；Phase 3 是独立、可关闭的扩展，不得放宽默认行为。
- **NR-007**: 已确认的 AI 结构与手工创建结构在持久化模型中语义相同，不新增永久 `aiGenerated` 标记，不让备份依赖外部平台。

### Key Entities

- **TemplateProposal**: 一次创建模式的会话期完整模板草案，包含版本、理由、警告和生成时结构指纹；确认前无持久化身份。
- **TemplatePatchProposal**: 面向一个既有模板的受限变更集合，保留目标模板与既有字段身份，只表达允许的小改。
- **StructurePackageProposal**: 一个领域草案、一个分类草案和一个模板草案组成的会话期父子结构包，带缺口理由和来源记录 ID。
- **TemplateUsageSummary**: 本机从当前账号记录中派生的非正文统计，如使用次数、活跃天数和最近使用日期；可重算、不持久化、不跨账号。
- **ProposalContext**: 账号会话标识的不可外发绑定、入口模式、目标对象 ID、结构指纹、请求 ID 与过期状态，用于阻止迟到和陈旧应用。
- **WorkflowAdapter**: 产品同源服务端与成熟工作流平台之间的窄适配边界，只接收白名单输入并返回统一提案，不拥有产品写能力。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 自动化证明空输入首次路径始终为 `0` 个外部请求，明确输入的一次生成动作最多 `1` 个工作流请求和 `1` 个完整模板提案。
- **SC-002**: 合成非法响应测试证明所属分类、记录类型、输入模式、周期、字段删除/重排/换 ID 等越界优化有 `100%` 被拒绝，确认前目标模板和记录 payload 字节不变。
- **SC-003**: Agent 对可复用现有分类的样本产生 `0` 个新结构包；对明确结构缺口的样本最多产生 `1` 个完整结构包，并且确认后原记录分类和正文仍不变。
- **SC-004**: 账号切换、结构并发修改、停止、超时、离线和迟到响应场景均产生 `0` 次错误写入、`0` 次跨账号显示和可继续使用的本地降级。
- **SC-005**: 路由与适配器测试证明外发字段白名单、认证、限流、大小、超时、no-store 和无写权限边界；真实平台 PoC 只使用合成数据并保留可核对运行日志。
- **SC-006**: 320/390/426/768/1280px 的入口和预览满足 44px、键盘、焦点、文本换行与无横向溢出，`npm run design:check`、聚焦回归、`npm run check` 和 `git diff --check` 通过。
- **SC-007**: 在 14 天隔离观察中记录使用次数、确认/拒绝、无效提案、可感知延迟与费用；确认率至少 50%、无效提案不超过 20%、正常成功请求中位可感知延迟不超过 8 秒，才讨论扩大启用范围。

## Scope Boundaries *(mandatory)*

### In Scope

- 本地默认零请求路径、一个完整模板创建提案、一个已有模板保守补丁、一个 Agent 新结构包提案。
- 统一结构化 proposal schema、同源平台适配器、输入/输出校验、结构指纹、预览确认、取消和降级。
- 成熟平台 PoC 与可替换工作流版本配置；合成数据验证、测试、隐私/费用/移除边界。

### Out of Scope

- 强制首次登录问卷、首页常驻 AI 按钮、一次生成整套领域树、后台自动整理或周期性自我优化。
- 自动移动/批量修改历史记录、改写原文、自动删除/合并结构、跨账号学习、共享记忆、向量库或可自写长期记忆。
- 通用多 Agent 平台、任意工具调用、Agent 直接写 Supabase、插件市场、日程/提醒/任务执行。
- 医疗诊断、投资建议、行为评分、因果结论，以及未获批准的真实私密记录外发。

## Assumptions and Dependencies

- `LN-077` 仍为待规划项；真实记录实施依赖 `LN-007` 的 AI 数据边界和 `LN-009` 的扩展分类反馈闭环决策，且不得弱化 `LN-069/LN-071` 的安全约束。
- `LN-022` 的手动模板创建、编辑、复制和预览继续是失败降级与人工兜底。
- 首期“过去的记忆”只使用当前模板和可重算的非正文统计；若未来需要历史原文、接受/拒绝历史或长期偏好模型，必须另立规格并完成 `LN-008` 数据模型、删除、备份与隐私评审。
- 平台选择、云端/自部署方式和模型提供方属于实施方案；不改变本规格的零写权限、结构化提案、显式确认和本地先写产品契约。
- 自动化使用合成账号、结构和记录；真实平台中文质量、费用与隐私信任需要独立人工证据。
