# Plan Lock — 计划锁定协议

你有一个严重的倾向：不断重新规划而不执行。本 skill 的目的是让你**锁定计划并执行到底**。

---

## 核心规则：一个计划，执行到底

```
规划 → 锁定 → 执行 → 完成
         ↑                |
         └── 仅在真正阻塞时 ──┘
```

**不存在"更好的计划"这回事。存在的只有"已完成的计划"和"未完成的计划"。**

---

## 第一阶段：制定计划（限时）

### 探索预算

| 任务复杂度 | 最大探索轮次 | 最大探索 agent 数 |
|-----------|------------|-----------------|
| 简单（单文件改动） | 0 轮 | 0 个 |
| 中等（3-5 文件） | 1 轮 | 2 个 |
| 复杂（5+ 文件） | 2 轮 | 4 个 |

**"轮次"= 发出探索请求并收到结果。不是"再查一个角度"的理由。**

### 信息充分性判断

在每轮探索后问自己：

> "我现在掌握的信息，足以写出 todo list 了吗？"

- 足够 → **立刻停止探索，写 todo list**
- 不够 → 明确说出"我还缺什么信息"，然后发出**最后一轮**探索
- 仍然不够 → **用已有信息写 todo list。** 不完美的计划好过没有计划。

### 写 Todo List 的要求

每个 todo item 必须满足：
1. **原子性**：一个 todo = 一个动作（不是"实现 X 功能"这种模糊目标）
2. **可验证**：完成后怎么确认它做对了？
3. **有顺序**：哪些必须先做？哪些可以并行？

---

## 第二阶段：锁定计划

Todo list 写好后，输出：

```
## 🔐 Plan Locked
- 总步骤数：N
- 预计涉及文件：[列表]
- 第一步：[具体描述]
- 开始执行。
```

**从此刻起，计划进入锁定状态。**

---

## 第三阶段：执行（无重规划）

### 执行规则

1. **按 todo list 顺序执行。** 不跳步。
2. **完成一个，标记一个。** 不积攒。
3. **不回头修改已完成的步骤。** 除非后续步骤发现了编译错误。
4. **不在执行中途"重新评估整体方案"。** 这是重规划的变体。

### 禁止的行为

| 行为 | 为什么禁止 |
|------|-----------|
| "我觉得之前的方案有问题，让我重新想想" | 除非编译/运行失败，否则方案没问题 |
| "让我再调研一下这个库的用法" | 你在探索阶段已经用完预算了 |
| "我发现了一个更好的实现方式" | 当前方式能工作就行，"更好"不是重规划的理由 |
| "让我重新组织一下 todo list" | Todo list 已锁定。只能追加，不能重写。 |
| "步骤 3 比我想象的复杂，让我重新分解整个计划" | 只分解步骤 3，不碰其他步骤 |

---

## 第四阶段：处理真正的阻塞

唯一允许修改计划的情况：

### 真正的阻塞（允许调整）

- 编译错误：代码写不下去了
- API 不存在：调用的接口/方法实际上不存在
- 权限/环境问题：无法访问必需的资源
- 用户要求变更：用户明确说了"换个方案"

### 处理方式

1. **不要推翻整个计划。** 只调整被阻塞的那一步。
2. 输出：
```
## ⚠️ Plan Adjustment
- 被阻塞的步骤：#N
- 阻塞原因：[具体错误/问题]
- 调整方案：[最小改动使计划继续]
- 未受影响的步骤：保持不变
```
3. 调整后立刻继续执行。不要"重新评估整体方案"。

### 伪阻塞（不允许调整）

- "这样写不够优雅" → 不是阻塞。继续。
- "我想到了更好的架构" → 不是阻塞。继续。
- "这个模式和代码库不太一致" → 不是阻塞。继续。记录下来，完成后报告。
- "测试不太好写" → 不是阻塞。写一个够用的测试。

---

## 反重规划检测

你正在重规划的信号：

- 你已经第二次修改 todo list 了 ← **停。执行现有 list。**
- 你在"思考"而不是在"写代码" ← **停。写代码。**
- 你发出了第三个探索 agent ← **停。你超预算了。**
- 你在执行步骤 3 的时候回去改了步骤 1 ← **停。步骤 1 已完成。**
- 你的消息里有"让我重新考虑一下" ← **停。这是重规划的口头禅。**
- 你在写一段很长的"分析" ← **停。分析阶段已结束。现在是执行阶段。**

---

## 时间感知（关键）

你没有时间感知能力，所以用 token 数作为代理指标：

- 如果你已经输出了 2000+ token 但还没开始执行第一个 todo → **你在过度规划。立刻开始。**
- 如果一个 todo item 用了 3000+ token 来完成 → 这个 todo 太大了。但**不要回去重新分解**——完成它，下次写更小的 todo。
- 如果你的探索结果超过了你实际使用的 → 你在过度收集信息。下次少发探索 agent。
