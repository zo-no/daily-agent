# Change Contract — 变更契约

在读取完项目事实源、检查 dirty tree 后，编码前写一份简短契约。契约用于约束实现，不是额外的设计文档。

```text
目标：本次需求要改变的可观察行为
Canonical path：当前行为的唯一主实现路径
复用位置：将直接复用的模块、函数、组件、schema 或持久化入口
删除/替换位置：本次范围内不再成立、会造成重复或冲突的旧逻辑
必须保留的旧逻辑：保留项及原因（兼容、迁移、回滚或外部契约）
确实需要新增：只有无法通过复用、替换或删除完成的文件、函数、状态或持久化路径
公共契约：路由、导出、数据结构、错误语义和调用方约束
不变量：产品、架构、权限、离线、本地优先、备份和 AI 安全边界
验证命令：聚焦回归、类型检查、lint、构建或其他质量门禁
未解决证据：缺失的凭据、生产观察、 owner 决策或并发冲突
```

## 使用规则

1. 先写“复用”和“删除/替换”，再写“确实需要新增”。
2. 每个新增文件、public export、状态写入者或持久化路径都必须有不可替代的理由。
3. 如果 canonical path 跨文件，所有必要调用方、测试和接口调整都列入契约；不得用“最小 diff”掩盖不一致。
4. 如果发现契约之外的改动，暂停并将其归类为必要追加或范围外发现。
5. 完成时逐项核对契约，并与变更指标一起报告；未验证的项目保持“未解决证据”。
