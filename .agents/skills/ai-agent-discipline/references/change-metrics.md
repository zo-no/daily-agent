# Change Metrics — 变更指标

指标服务于“相同逻辑下更少、更核心、更干净”的目标。它们用于发现重复路径和复杂度增长，不用于鼓励机械删行。

## 硬门禁

| 指标 | 默认目标 | 说明 |
| --- | ---: | --- |
| 行为回归 | 100% 通过 | 相关单测、聚焦 E2E 和质量门禁不能回归 |
| 新增平行行为路径 | 0 | 同一行为只保留一条 canonical path；兼容路径必须有移除条件 |
| 状态写入者 | 不增加 | 新增写入者需记录状态所有权和一致性理由 |
| public export / API | 默认不增加 | 新接口必须有稳定调用方和迁移/移除计划 |
| 新增死代码 | 0 | 新增导出、分支、文件都应被调用或测试覆盖 |
| 新增依赖循环 | 0 | 保持既有单向依赖边界 |
| 范围内可替换旧代码删除率 | 目标 100% | 被替换且不再需要的旧路径不得遗留；兼容、迁移或回滚保留项不计入分母 |

## 解释性指标

- **Reuse ratio** = 复用的既有行为点 ÷ 本次行为点总数。目标是优先复用；无法客观计数时列出复用位置。
- **Semantic additions / deletions**：只统计新增或删除的行为、状态、契约和分支，不统计空格、重排和机械改名。
- **Net semantic change** = semantic additions − semantic deletions。净变化应与需求规模相称；大于预估 2 倍时暂停检查。
- **Semantic diff density** = 语义变化点 ÷ 变更文件数。密度过低通常意味着格式化或无关重构，密度过高通常意味着应拆分任务。
- **圈复杂度、嵌套层级、调用跳转层级**：以现有项目工具或局部比较为准；当前行为不变时，默认不应增加。若增加，必须说明为何不能通过替换或抽取既有主路径避免。

## 交付时的最小报告

```text
行为回归：通过/失败（命令）
平行路径：0 或说明兼容路径及移除条件
状态写入者：变更前 N → 变更后 N
public export/API：变更前 N → 变更后 N
语义新增/删除/净变化：A / D / A-D
Reuse ratio：约 X%（列出复用点）
复杂度：圈复杂度、最大嵌套、调用跳转是否变化
未验证项：明确列出，不用“应该没问题”替代
```
