# 记录工具与拖拽社区实践调研

> 本文件记录证据和选择理由，不覆盖 `规范/` 中的正式规则。

## 结论

Log Note 使用 dnd-kit 处理 React 多容器排序，并保留显式菜单作为无障碍和低精度输入的备用路径。

## 参考实践

- [dnd-kit 文档](https://docs.dndkit.com/)：提供 sortable、多容器、鼠标、触摸、键盘 sensor 和 drag overlay。
- [dnd-kit Accessibility](https://docs.dndkit.com/guides/accessibility)：拖拽把手需要可聚焦语义，支持 Enter/Space、方向键、Escape，并提供本地化说明和 live region 播报。
- [WAI-ARIA Rearrangeable Listbox Example](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/examples/listbox-rearrangeable/)：移动后保持焦点，提供键盘替代操作和可理解的移动确认。

## 方案取舍

- 选择 dnd-kit：与当前 React/Next.js 架构匹配，多容器排序和 keyboard sensor 成熟。
- 未选择只依赖 HTML Drag and Drop：移动端和键盘体验不稳定。
- 未让整行可拖动：会与点击编辑、滚动和文本选择竞争。
- 保留 Move up / Move down / Move to…：拖拽不是唯一完成任务的方式，也便于精确跨组移动。

## 移动端注意事项

- 使用约 180ms 延迟和 6px 容差，降低滚动误触。
- 长列表使用 drag overlay，避免被裁剪或造成布局跳动。
- 空容器必须有真实 droppable 区域，不能只在已有子项上接受放置。
