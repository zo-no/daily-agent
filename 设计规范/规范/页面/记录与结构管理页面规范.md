# 记录与结构管理页面规范

## 记录页

- MUST 在时间与分类记录视图中以当前日期和记录内容作为首要信息，新增与导出操作并列固定可达；日计划模式改为只显示其上下文内的新增计划操作。
- MUST 区分线性记录和周期记录：前者按时间线展示，后者按模板节奏和值展示。
- MUST 让固定/周期记录优先在首页模块内完成：单值直接输入，结构化字段在当前条目下方展开；不得为可在当前上下文完成的填写强制打开弹窗。
- MUST 将固定记录区块标题旁的完成数与管理入口视为同一辅助工具簇：完成数使用 `12px` 等宽数字、`500` 字重和弱色，“调整”使用 `14px`、`500` 字重；二者同一行紧邻排列并明显弱于 `22px` 区块标题。“调整”的可见文字可以克制，但触控与键盘焦点区域不得小于 `44px`，不得用胶囊、粗边框或高饱和底色把该工具簇提升为第二标题。
- MUST 将固定记录行前方的领域名称视为辅助归属标签：保留在记录名前方，使用 `12px`、`500` 字重、弱色与低对比轻量表面；记录名继续使用 `16px` 主信息样式。标签不得形成与记录名竞争的第二标题列，也不得改变整行至少 `44px` 的触控高度。
- MUST 让固定记录位于当天时间线或分类分组内容之后；空时间线不得用视口最小高度或大块空状态制造无意义留白。
- MUST 在窄屏与宽屏都保持“快速新增 → 当天内容 → 固定记录”的阅读顺序，不得形成卡片墙或横向滚动。
- MUST 将 600–800px 视为紧凑桌面/平板工作区：顶栏保持单行，日期标题使用展示字号下限，时间线与固定记录限制为可扫描阅读簇；不得把手机端的整宽值列和放大标题直接拉伸到该区间。
- MUST 让新增记录默认进入最短填写路径，不在首屏要求维护领域或分类结构。
- MUST 保留时间视图和分类视图，两种视图使用同一记录数据。
- MUST 将“时间 / 分类”作为日记浏览专用的浅色下划线 Tab，固定在共享日期上下文下方；不得把记录视图选择塞进顶栏或计划画布。右下快速操作区改为唯一的“日记 / 计划”工作区切换，在记录与计划两种模式均可达；计划模式隐藏导出/新增记录，仅将该切换置于新增计划 FAB 上方，且不得遮挡当前上下文的新增计划按钮。
- MUST 将月概览收敛为日记与计划共用的折叠日期上下文，不得作为与时间/分类并列的第三视图。顶部必须把“所选日期 + 次级星期 + 展开箭头”融合为同一个日期组件，不得再拆成独立月份行、日期行或前后箭头组；日期使用日记式主标题，星期以更小字号、弱色和 8–16px 间隔表达从属关系。收起与展开必须保留同一标题 DOM，任何状态都不得额外显示月份标题、统计或活动摘要。首页整个可视工作区 MUST 作为横滑命中面：收起时切换前后日，展开时切换前后月，但应用顶栏、纸面内容与上下文浮动操作 MUST 保持视觉稳定。横向意图锁定后 MUST 显示覆盖完整 viewport、但深色视觉范围在 `min(44vw, 420px)` 内衰减完毕的线性方向阴影：向右拖时左边缘最深并向右透明，向左拖时镜像。同时 MUST 显示一个温暖石墨灰圆角日期铭牌，完整显示本地化目标年月日，以约 `150ms` 的淡入缩放出现；左滑时固定在 viewport 中轴左侧一个受限步长处，右滑时镜像到右侧，纵向保持居中。铭牌不得跟随手指、吸附标题、显示箭头或引发页面位移。除该铭牌外，不得渲染手柄、额外胶囊、楔形幕布或其他方向组件。页面、顶栏、日期、正文和浮动操作不得位移、缩放或交叉淡化。小幅未达阈值的移动必须让阴影与铭牌同步回收；达阈值后两者快速消退并完成既有日期/月更新。滑动 MUST 保留纵向滚动；输入、弹窗和相邻月份轨道 MUST 保留自身交互，reduced-motion 下 MUST 近乎即时完成。组件下只依次显示开放式 7 列月格与可横向浏览的相邻月份轨道，月格内部不得重复月份标题、统计或箭头组。点击日期展开月格、日期按钮、月份轨道与键盘网格导航 MUST 保持可达，确保滑动不是唯一选日方式。
- MUST 在 320–700px 让上述唯一日期组件直接占用应用顶栏的身份位置并隐藏可见 `Log Note` 品牌块；日记工作区不得再渲染第二个日期标题。日期/星期/展开箭头位于顶栏首层，移除前后箭头后 341–700px 顶栏 MUST 收回单行；320px MAY 用日期行与工具行保护完整文字和 44px 触控。语言、搜索、结构和设置继续完整可达。701px 及以上 MUST 保留品牌第一行与同一日期 DOM 的第二行。不得通过复制日期按钮、绝对定位覆盖或删除品牌资产实现该响应式重排。
- MUST 用圆形强调选中日，以小信号点区分当天存在记录或计划；不得把记录/计划数量做成抢眼数字徽标，也不得使用厚表格边框制造后台日历感。
- MUST 让日期点击立即更新当前时间记录、分类记录或日计划画布，并保持月历展开，不得再显示当天摘要、“查看记录”或“计划这一天”等二次确认动作。Escape MUST 收起月历并把焦点还给月份入口。从时间记录切换到其他日期记录必须不超过“展开日期选择器 → 选择日期”两步。
- MAY 从当前所选日期进入独立“日计划”次级表面，以纵向小时轴创建和编辑本地计划时间块。页面层级 MUST 固定为“应用顶栏 → 融合日期导航 → 可选月历 → 记录/日计划切换 → 下方当前内容”；记录与日计划 MUST 复用同一顶部 DOM、尺寸和折叠行为，模式切换只能替换最后一层，不得收起月历、重置所选日期或改变当前月份上下文。日计划内选日 MUST 直接更新下方同一时间画布。时间画布应占满上方日期上下文以下剩余 viewport 并内部滚动，新增计划 FAB MUST 始终完整位于可视 viewport 内。计划必须与原始记录分层、可单独移除，且不得新增记录必填步骤、首页首要 CTA、提醒或网络前置条件。经显式授权连接 Google Calendar 时，连接与同步操作 MUST 只位于账号设置的次级区块；Log Note 创建的本地计划 MAY 同步为带私有来源标记的主日历事件，Google 原有事件 MUST 在日计划中以只读来源展示且不得被 Log Note 修改或删除。全天事件 MUST 使用独立全天区域，不得伪装为 `00:00` 时间块。拒绝授权、离线、限流或 API 失败 MUST 保持本地计划可编辑且不得删除已有缓存。
- MUST 确保 320/390/600/671/768/1280 六档日期选择器与日计划无横向溢出，关键触控目标不少于 44px；展开后必须仍可识别当前记录表面的起点，浮动操作不得造成记录入口不可达。
- MUST 在分类视图中按领域 → 分类共置普通记录、已填写固定记录和未填写固定模板；固定记录不得脱离所属分类集中成第二套信息架构。
- MUST 让分类视图的视觉阅读顺序与数据层级一致：领域最强、分类次之、具体记录或指标再次之、值与辅助信息最后；使用递进缩进和留白，不使用贯穿分类内容的装饰性竖线。
- MUST_NOT 在记录页把导入或预置的领域、分类、模板数量呈现为普通记录数据；领域标题与普通记录分类标题不显示冗余计数。包含可见周期模板的分类 MUST 显示“已完成数/可填写总数”，未填写模板计入分母，零完成状态仍显示，隐藏模板不参与比例。
- MUST 让分类视图中的固定模板继续支持原地填写、更新和清空；已填写周期记录不得同时作为普通记录重复出现。
- MAY 在记录页的“时间 / 分类”共享切换栏右侧提供一个按文字宽度收敛的次级“智能整理”按钮；它 MUST 在时间与分类视图中保持同一位置，不得因切换视图出现、消失或下移到内容区。入口只保留动作名称和至少 `44px` 的命中区，不得使用说明区块、额外整行分隔或全宽按钮把它提升为首页主 CTA，也不得增加快速记录步骤。
- 智能整理 MUST 由用户主动选择一个自然日后启动，默认日期为今天；一次只预览并分析该日全部普通记录，周期记录必须排除。选日 MUST 复用首页的“月日 + 次级星期 + 展开箭头”触发器与开放式月格内核，不得回退为浏览器原生日期输入或独立“今天”按钮，也不得在日期触发器上方重复“选择日期 / Choose a day”等作用显而易见的标题；首页独有的全屏横滑、日记/计划联动不得被强行带入智能整理。智能整理选中具体日期后 SHOULD 收起月格并回焦日期触发器，以便立即阅读当天记录。日期上下文到当天记录的主区块分隔 MUST 优先使用区块留白；“当天记录”标题与其列表内容 MAY 使用一条弱分隔线，不得用两条等权横线表达两种不同关系。不得提供跨日范围、搜索、复选框、已选数量、全选或反选，也不得提供把同一标签批量写给整日记录的手动操作。
- 智能整理只能用本地可替换规则从已有标签中提出最多 3 个建议；低置信记录 MUST 保持不分类，建议 MUST 显示原因、置信状态和包含记录。桌面 MUST 使用“日期与当天记录 → 建议确认”的双栏工作区，移动端 MUST 按“日期 → 分析 → 确认”分步展示；不得把桌面双栏压缩成移动端横向滚动。
- 标签或分类变更 MUST 只在用户显式应用后写入，并提供移除单条、忽略、重算和撤销。原始 `entry.content`、`entry.categoryId`、快速记录链路、JSON schema 与备份语义不得改变。
- 智能整理 MUST 在无账号、无网络、无 API Key、无真实模型时完整可用；不得后台扫描、上传记录或自动创建标签/分类。
- MAY 在时间视图保留独立的固定记录填写区，以维持低摩擦记录路径；该展示差异不得改变记录的领域、分类或 Markdown 导出归属。
- MAY 在普通自由文本记录的二级详情中提供一张本地图片附件；默认编辑面不得新增必填步骤或常驻工具栏控件。
- MUST 将附件缺失、损坏或读取失败显示为不发起网络请求的占位，正文仍可编辑、保存、搜索和导出。

## 结构管理页

- MUST 使用一棵连续的领域 → 分类 → 模板层级树，不用标签页拆分管理上下文。
- MUST 让领域、分类和模板各自保持独立的名称、排序、归属和编辑能力，只合并管理界面，不合并数据概念。
- MUST 允许从同一层级树进入全部结构管理，也允许从首页“调整固定记录”进入仅突出周期模板的聚焦视图。
- MUST 让导出在页面顶部稳定可达，并导出当前 JSON 顺序和父子关系。
- SHOULD 保持列表紧凑，管理动作不应让页面看起来像后台仪表盘。

## 设置页

- MUST 将设置页作为独立控制面，并按用户任务而不是技术对象组织。桌面使用稳定的左侧设置索引与单一活动面板；`760px` 及以下使用“完整设置索引 → 单一全宽详情”的两级移动导航，不得把分区藏在横向滚动 Tab 中。移动设置首页必须一次看全常规、账号、下载、恢复、图片五项，只出现一个“设置”标题；详情页顶部返回动作回到设置索引。索引项和全部主要操作不得小于 `44px`，切换面板不得造成页面横向溢出。
- MUST 把所有产生文件的操作按亲密度合并到“下载”：今日/全部记录、下载格式、完整/文字备份、当前结构和起步示例在同一面板内分组；“恢复”独立承载导入、校验、确认与替换风险；“图片”只管理图片占用与清理；“常规”只保留语言与添加到主屏幕。一次只渲染一个一级任务，保留 `/settings#export`、`#backup`、`#structure`、`#storage` 及新别名的兼容映射。页面使用连续纸张、标题、留白和细分隔线表达层级，不得演变为设置卡片墙。
- MUST 删除或避免“选择设置”“记录保存在哪里”“本地使用”“保存在此设备”等重复、抽象或不准确的界面标题。移动索引副信息应展示当前语言、记录数、恢复动作、图片数/容量等不同状态，不得用四句结构相同的说明复述栏目名称。浏览器数据边界只在下载备份组和图片区各保留一次必要说明。
- MUST 对语言切换等结果显而易见的常规控件只保留名称、当前状态和操作，不再解释其作用；添加到主屏幕只保留一个可执行提示，不并列重复“效果说明 + 操作说明”。同组分隔线只允许出现在相邻设置项之间，首项上方和末项下方不得再画无归属的装饰线。
- MUST 将账号作为可选次级设置任务：以 Supabase 邮箱密码作为国内网络下的主要账号路径，以 Google 作为替代路径；不得用浏览器随机 ID 冒充可访问数据库的本地账号。“无账号使用”通过直接返回记录页表达，不需要创建本地身份或密码。不得把账号变为首次启动、记录、浏览、搜索、编辑、备份恢复或离线使用的前置条件。邮箱密码表单 MUST 使用明确标签、密码遮罩、至少 8 位校验、登录/注册熟悉切换和不少于 `44px` 的操作；密码只能交给 Supabase Auth，不得写入本地 state、日志、数据库文档或备份。登录后 MAY 展示独立的云端保存组，但登录本身不得上传；保存必须明确列出文字记录、日计划、结构和设置，并明确图片仍在本机。覆盖云端或本机前必须确认，云端恢复前必须下载完整便携回滚备份；revision 变化必须停止覆盖。不得加载远程头像，不得把 OAuth code、token、session、user ID、workspace 或 revision 写入 Log Note JSON/便携备份或 Service Worker 缓存。缺配置、拒绝授权、过期、离线与服务失败均不得改变本地记录状态；退出失败时必须保留真实登录状态并明确提示，不得虚假显示已退出。
- MUST 让下载页主阅读顺序固定为“记录 → 备份 → 记录结构”，三组使用 `18px` 小标题、`4px` 标题说明间距和 `32px` 跨组间距。Markdown 下载格式必须作为记录组内的内缩渐进设置，不得形成第四个等权区块；浏览器记录/图片数量使用 `12px` 等宽元信息并紧邻“备份”标题，换设备提示使用下一行 `14px` 说明；“推荐”必须贴近“完整备份”名称，不得漂移到行尾成为独立状态列。
- MUST 明确便携备份包含记录、结构与本地图片，是存在图片时的推荐完整备份；JSON 备份只包含文字状态与图片引用，不得暗示包含图片文件。导出与“恢复并替换”必须分组，恢复区常驻说明替换范围与 JSON 图片影响，并继续在完整校验后请求确认。
- MUST 在本地 payload 损坏或迁移失败时进入可见恢复模式：普通 Markdown、JSON、便携与当前结构导出及设置编辑必须暂停，临时默认 state 不得被描述或导出为真实档案；浏览器确实返回原始 payload 时，用户必须能逐字下载；若存储读取在取得原值前失败，则必须明确说明无法生成恢复文件，禁止导出伪造内容。两种状态都须继续允许从有效 JSON 或便携备份恢复，且恢复成功后才解除保护。
- MUST 为 JSON 文件设置读取前体积上限；取消、超限、损坏、校验失败或本地持久化失败均不得改变当前 state 或附件 Blob。清理图片只能移除当前已持久化 state 未引用的 Blob，在恢复保护期间必须禁用。
- SHOULD 将 Markdown 格式作为导出领域内的渐进展开高级设置，桌面可使用字段与 sticky 预览双栏，中窄屏改为单栏；预览必须有可访问区域名称，恢复默认保持次级视觉。
- MUST 保持中英文切换只改变界面语言，不翻译或改写记录；本地存储和安装说明不得暗示自动同步。账号页只有在真实登录且数据库可用时才可显示云端版本，文字云端保存不得冒充图片完整备份。

## 数据边界

- 活跃工作副本 MUST 继续使用版本化 JSON 与浏览器 `localStorage` 保存文字和结构；获准的本地图片二进制 MUST 独立保存在 IndexedDB，不得写成 data URL 或 base64 状态。已登录用户 MAY 显式保存带 revision 的文字快照到受 RLS 保护的 Postgres；登录不得自动上传，CAS 冲突不得 last-write-wins，图片未进入私有 Storage 前必须从云端 payload 移除引用并显示真实限制。
- MUST 提供文字/结构 JSON、带附件校验的便携备份、结构 JSON 和 Markdown 导出。
- MUST_NOT 因视觉或排序改造修改已有日记正文。
- MUST_NOT 自动上传附件、默认加载远程图片，或让图片失败阻止文字记录保存。
