# 反馈与动效规范

## 正式规则

- MUST 让动效解释状态变化，不承担装饰或页面表演。
- MUST 遵守 `prefers-reduced-motion`，将非必要动效降到近乎即时。
- SHOULD 使用 140–180ms 处理 hover、focus 和简单状态切换。
- SHOULD 使用 180–240ms 处理拖拽升起、排序位移和落位。
- SHOULD 在拖拽时只增加轻微阴影、位移和透明度变化。
- MUST 用 toast 或 live region 确认需要用户知道的保存、导出和排序结果。
- MUST_NOT 用循环动画、弹跳或大范围页面过渡干扰快速记录。

## 验收

- 快速连续记录不会被动效阻塞。
- 拖拽中的源位置、浮层和目标位置可以明确区分。
- 屏幕阅读器播报使用人类可理解的名称，不播报内部 ID 或零基索引。
